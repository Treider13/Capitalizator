## Простыми словами

**К началу обучения программа готова наполовину.** Код, который **пишет рынок**, уже есть. Живого рынка он ещё не пишет: нет VPS и нет часа BTC. Учиться не на чем.

Обучение сейчас = записывать сделки и стакан. Не торговать. Не склеивать жюри.

**Склейка не нужна сейчас**, потому что склеивать нечего: жест и свеча считаются с живой ленты. Ленты нет. Склеить модули на фикстурах — не обучение, а ещё один тест.

**Что делать тебе (не код):** арендовать VPS у Bybit → поднять уже готовый рекордер → час BTC → сутки без дыр. После суток обучение **началось**. Склейку (жест+свеча+жюри в одну строку) делаем, когда лента уже капает.

**Где будет склейка.** Её ещё нет. Куски лежат в разных файлах. Склейка — новый маленький процесс на том же VPS, что рекордер. Он читает уже записанную ленту и по каждому касанию зовёт по очереди: зона → CAV → ZLG → лента/BTC → жюри → строка тени (`ShadowWriter`, `sent=false`). Это не кнопка ордера (`propose`) и не сам рекордер. В плане это шаг 4.17, после житых суток. Файл оркестратора пока не создан — создавать сейчас не надо.

**Как склеить, когда сутки уже есть.** Ты руками модули не склеиваешь. Пишется один короткий цикл (новый файл, его ещё нет). На каждую сделку с ленты он зовёт уже готовые функции:

1. `Registry.on_trade` — цена в зоне? если да, касание
2. `cav.label` → `fill_cav` — свеча
3. `ZLG.classify` → `fill_gesture` — жест книги
4. `fill_tape` / `fill_btc` / `fill_prs` — лента, BTC, пружина стакана
5. `stamp_jury` — жюри (согласие или тишина)
6. `ShadowWriter.write` — строка в журнал, ордера нет

Это и есть вся склейка. Один повар, ингредиенты уже в коробках. Делает программист или агент **после** живого часа/суток, не ты в Excel и не сейчас.
