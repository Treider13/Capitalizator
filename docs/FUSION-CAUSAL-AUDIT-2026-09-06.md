# Fusion: повторный аудит причин и интеграций, 6 сентября 2026

Исторический результат первого прохода PR #46. Дополнительные исправления и текущие проверки: [аудит по skills](FUSION-SKILLS-AUDIT-2026-09-06.md).

## Область проверки

Проверена версия после слияния PR #45: main `6cb7636d08ace8c77517376e7eadfa8b118397aa`, дерево `9da5ba36a9408b5c1bc0a76e6e479ad937e489aa`. Локальная исходная версия имела в точности то же дерево. Исправления относятся к исполняемому Fusion, его общим данным, тестам и документации. Зависимости старых исследовательских модулей не удалялись ради косметической уборки. Основной deployment запускает Fusion; legacy deployment остаётся отдельно.

Это проверка программной реализации и конкретных отказов, а не сертификация безубыточности. Доходность 30% в месяц, отсутствие всех возможных гонок и превосходство над всеми стратегиями не установлены. Авторизованные заявки Demo/Live, развёртывание на сервере и двухлетний рыночный backtest в этой среде не выполнялись.

## Воспроизведённые причины и исправления

Регрессии находятся в `tests/fusion/test_causal_audit.py`. Первые восемь проверок действительно падали на исходном коде: три варианта потери типизированной новости, потеря supply context, позднее сообщение New, повтор отмены, голодание команд и будущий timestamp счёта. Дополнительные проверки охватывают интеграции ниже.

| Причина | Изменение и проверяемый результат |
|---|---|
| Старое объединение новостей отбрасывало unlock/security/suspension без подходящих слов | Типы `unlock_blackout`, `surprise_blackout`, `linear_supply_context` сохраняются явно; первые два запрещают вход в своём окне, supply остаётся контекстом |
| Источник анлоков мог засчитаться за новости монеты | RSS-покрытие и unlock-покрытие проверяются раздельно; тест ARB с одним unlock-источником не получает news coverage |
| Готовая срочная новость ждала самый медленный источник | Публикация после каждого завершённого источника; тест удерживает медленный запрос и проверяет доступность быстрого результата до его окончания |
| Реакция на новость зависела от очередного торгового блока | Общий обработчик news→refutation/flatten вызывается брокером и replay; сохраняется защита остаточной позиции после отмены частично исполненного входа |
| Автоматический макрокалендарь отсутствовал | Отдельный поток обновляет BLS, BEA и Fed; проверяются timezone, DST, первое получение, истечение покрытия, отменённые события и календарные границы |
| Запоздалый New возвращал отменённую заявку в accepted | Переходы состояния не откатывают терминальную отмену; реальный Filled, пришедший в гонке с отменой, учитывается |
| Ожидание подтверждения cancel порождало REST flood | 20 вызовов tick прежде отправляли 20 отмен; теперь отправляется одна до следующего срока reconcile. Бюджет повтора долговечен |
| LIMIT 16 оставлял последующие команды без обслуживания | Очередь учитывает последнюю попытку; ошибка одной команды не пропускает остальные в партии; 17-я команда обслуживается |
| 16 действующих resting orders занимали выборку перед 17-м pending | В выборку входят только заявки, требующие отправки/отмены; тест с 17 инструментами подтверждает отправку последней |
| Несколько причин выхода создавали конкурирующие закрытия | Один незавершённый flatten на режим/символ; до завершения закрытия новый вход запрещён |
| Timestamp счёта из будущего считался свежим | Допустимый возраст ограничен с обеих сторон: `0 <= age <= account_age` |
| Ручная прибыль Demo могла квалифицировать политику бота | Для допуска Live учитываются эпизоды, вход которых принадлежит текущей политике; смешанная история не квалифицирует. Общая статистика счёта продолжает показывать ручные сделки |
| График показывал исходный SL после изменения биржевого | Отображаются фактические позиции и SL venue; private position обновляет их без обновления возраста кошелька; старые сообщения/REST не откатывают более новое состояние |
| Границы сессий исчезали внутри 4h свечи | Сервер вычисляет точные UTC-границы через IANA; график использует положение внутри свечи; добавлены timestamp-сегменты тренда и RSI-дивергенции |
| Частое обучение конкурировало с обработкой стакана | Математика Atlas перенесена в отдельный spawn-процесс, одна задача одновременно, BLAS=1; тест сравнивает коэффициенты/отчёт с исходным train и проверяет завершение дочернего процесса |

Новая таблица `dispatch` добавляется без удаления существующих orders/commands. Политика обновлена до `fusion-3-causal-news`; новая конфигурация меняет её хеш. Старые обученные состояния и результаты Demo не выдаются за квалификацию изменённой политики.

## Матрица требований

| Требование | Исполняемое место и фактическая граница |
|---|---|
| AMD | `structure.py`, `context.py`: диапазон, sweep/reclaim, направленное движение; наблюдаемые признаки, не доказательство намерения манипулировать |
| Карта ликвидности и sweep до входа | Подтверждённые экстремумы/равные уровни, HTF POI + LTF возврат; закрытые стопы участников биржа не раскрывает |
| Крупные игроки | Аномалии принтов, объёма, CVD, OI, ликвидаций; не идентификация владельца и не гарантия, что крупный принт открывает позицию |
| Правильный вход | Контракт с последующим контрольным блоком, сроком, актуальной ценой, новостями, риском и RR после издержек |
| HTF/LTF | 15m→1m, 1h→5m, 4h→15m; закрытые бары и подтверждённые pivots |
| FVG / BAG / Imbalance | FVG, OB и явно определённый двухбарный BAG; зоны и их состояние доступны графику |
| Сессии / профиль | Tokyo/London/New York с DST, реальный trade-volume profile, POC и смежная VA 70%; частичный первый профиль помечен и не используется как полноценная цель POC |
| Fibonacci / OTE | Направленные якоря; допустимая половина отката 0.5–1; OTE 0.618–0.786 как зона интереса, не обещание преимущества этих чисел |
| Объёмы | Подписанные принты, Delta/CVD, горизонтальный профиль, OI/ликвидации и аномалии |
| Теханализ / RSI | Подтверждённые трендовые линии, фигуры, дивергенции; контекст, не независимые голоса за сделку |
| Айсберги | Пополнение против агрессии при слабой реакции цены; вероятностный proxy, L2 без order IDs не доказывает айсберг |
| Gamma flow | Публичные option OI/Greeks/IV, unsigned gross gamma и концентрация страйков; знак дилерской позиции неизвестен |
| Боковик | Диапазон/sweep и структурные цели, в том числе полноценный POC; вход всё равно проходит контракт и общие ограничения |
| ICT/SMC | BOS/CHoCH/OB, sweep, premium/discount как формализованный наблюдаемый контекст |
| Новости монет / анлоки | Bybit + настроенные официальные RSS/Atom + Tokenomist; словарный NLP и тип события, индивидуальная свежесть и известное время. Требуются доступные источники и Tokenomist key для соответствующих монет |
| Макрособытия | BLS/BEA ICS и годовой календарь Fed; ошибка/старение/неполное будущее покрытие блокируют вход |
| Обучение | Регулярное причинное переобучение ridge-ансамбля на созревших метках с хронологическими train/calibration/test, не PPO/SAC |
| Исполнение / риск | Один владелец сетевых изменений счёта, долговечная outbox, атомарный резерв, запрет пирамидинга, RR≥2, биржевой SL и ужесточаемый trailing |
| Demo / Live | Два реальных типа подключения Bybit; переход явный и требует квалификации. Нет обязательного ожидания суток BTC; достаточные данные/покрытие всё равно обязательны |
| Интерфейс | SSE, свечи, зоны, профиль, сессии, тренд, RSI-дивергенции, решения, новости, позиции/SL и исполнения; визуальная задержка по умолчанию до 200 мс между обновлениями |
| Проверка стратегии | Replay A/B/C/D с издержками, задержкой и частичными исполнениями реализован. Двухлетний OOS, полноценное сравнение с Buy & Hold/MA и доказательство прибыли не выполнены без подходящих данных |

## Проверки и измерения

Итоговый полный pytest: **2264 passed, 2 skipped за 93.79 с**. Добавлены 23 регрессионных случая. Пропущенные тесты не выдаются за выполненные.

- Ruff: все проверки src/tests и изменённого benchmark пройдены.
- Mypy: штатные 11 модулей и все 26 модулей Fusion проходят strict-проверку (внешние импорты Fusion проверяются в режиме follow-imports=silent).
- Offline wheel собран; побайтово сверены все 26 Python-модулей Fusion и dashboard, проверена зависимость threadpoolctl.
- DOM/canvas-проверка dashboard: 815 операций рисования, без ошибок. Это тестовый DOM, не запуск настоящего браузера.
- Потоки, HTTP/SSE, восстановление и исполнения проверяются тестами с управляемыми данными/адаптерами; авторизованная интеграция Bybit здесь не запускалась.

Стрессовый benchmark: два рыночных актора, суммарно 10 000 синтетических сообщений стакана, SQLite WAL/FULL, BLAS=1. Он измеряет локальный путь обработки стакана и журналирования, не полный путь сигнал→биржа→экран.

| Режим | Событий/с | p99 BTC / ETH, мс | Максимум BTC / ETH, мс |
|---|---:|---:|---:|
| Только стакан | 11 803 | 0.640 / 0.647 | 4.26 / 4.28 |
| Непрерывное обучение в том же процессе | 2 437 | 4.125 / 4.054 | 67.34 / 63.70 |
| Обучение в отдельном процессе | 9 761 | 1.408 / 1.407 | 125.85 / 133.07 |

В первом конкурентном прогоне завершено 440 fit, во втором 39, каждый на 1024 синтетических строках; изолированный прогон включает холодный spawn. Это не одинаковая фиксированная нагрузка и не гарантированный коэффициент ускорения. Результат показывает конкуренцию и улучшение p99 после изоляции, одновременно фиксируя худший максимум при холодном запуске. Во всех трёх прогонах сохранено 10 002 журнальных записи, ошибок нет, акторы и дочерний процесс завершены. Числа не являются SLA, HFT-сертификацией или торговой доходностью.

Воспроизведение измерения:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python tools/benchmark_fusion.py --help
# Варианты: базовый; --training-rows 1024;
# --training-rows 1024 --isolated-training. Остальные параметры фиксировать одинаково.
```

## Использованные инструкции и первичные источники

Применены необходимые навыки микроcтруктуры, риска, walk-forward, sentiment и визуализации из [agiprolabs](https://github.com/agiprolabs/claude-trading-skills), исследовательский workflow [DaviddTech](https://github.com/DaviddTech/ai-trading-agent) и инструкции [Bybit skills](https://github.com/bybit-exchange/skills). Не устанавливались несвязанные DEX/tax/copytrading-инструменты. Проверка обновления локального Bybit skill не смогла получить manifest; обновление не заявляется выполненным.

Изучены [Lumibot](https://github.com/Lumiwealth/lumibot), [HKUDS AI-Trader](https://github.com/HKUDS/AI-Trader) и [TauricResearch TradingAgents](https://github.com/TauricResearch/TradingAgents). Их наличие не доказывает преимущество нашей стратегии. Второй брокер и LLM-агенты не добавлены в критический поток отправки ордеров; сигналы и сделки во внешние платформы не публиковались. TraderDev не подключён, поэтому его backtest не выдаётся за выполненный.

- [Bybit Demo API](https://bybit-exchange.github.io/docs/v5/demo): Demo отделён от Testnet.
- [Cancel order](https://bybit-exchange.github.io/docs/v5/order/cancel-order): ответ запроса асинхронный, окончательное состояние подтверждается отдельно.
- [Private position](https://bybit-exchange.github.io/docs/v5/websocket/private/position): фактические позиционные обновления и updatedTime.
- [BLS CPI calendar](https://www.bls.gov/schedule/news_release/cpi.htm) и [официальный ICS](https://www.bls.gov/schedule/news_release/bls.ics).
- [BEA calendar subscription](https://www.bea.gov/news/schedule/icalendar) и [расписание](https://www.bea.gov/news/schedule).
- [Fed annual meeting dates](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) и [месячный календарь с 14:00/14:30](https://www.federalreserve.gov/newsevents/2026-january.htm).

Fed parser извлекает дату из годового календаря; 14:00 решения и 14:30 пресс-конференции — явно выбранная конвенция New York, а не час, прочитанный из этой страницы. Внеплановые события требуют новостей. BLS/BEA берут время из ICS; неподдержанные recurrence и даты без точного времени отклоняются. Протокольные fixtures проверены, но фактическая сквозная HTTP-загрузка всех трёх источников в этой среде не подтверждена: сетевые запросы были отменены до выполнения. На сервере это остаётся обязательной интеграционной проверкой; при ошибке система блокирует вход, а не подставляет фиктивное расписание.

## Что ещё требует фактических данных и среды

1. Проверить источники новостей/анлоков и официальные расписания из сети сервера, доступность будущих классов событий и timestamps первого получения.
2. Пройти авторизованный Demo цикл: create/partial fill/cancel/fill, private position, стоп/трейлинг, reconnect и сверка P&L/fees. Это не выполнено одними unit-тестами.
3. Проверить реальный браузер, график и задержку end-to-end на сервере; здесь браузер и Docker не запускались.
4. Записать или приобрести подходящую историю, выполнить независимый walk-forward полной стратегии, чувствительность к издержкам/задержкам и сравнение портфелей. Повторно используемая тестовая часть модели не заменяет нетронутый OOS.

Эти пункты не замаскированы заглушками и не объявлены завершёнными. Работающий программный механизм, доступность внешнего сервиса и доказанное торговое преимущество — три разные проверки.
