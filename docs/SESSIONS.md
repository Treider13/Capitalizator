# Сессии: стол торгует круглые сутки, отправка — по окну UTC

**Дата:** 2026-09-03 · Релиз «sessions». Заменяет единственное окно 16:30–19:30 МСК
(`risk/session.py`, `infra/time.yaml`) таблицей окон `infra/sessions.yaml` и модулем
`risk/sessions.py`. Тень и фейд по-прежнему торгуют на бумаге 24/7 (W3); политика
управляет только **отправкой** демо/лайв-интентов, размером, буфером стопа и бюджетом.

## 1. Почему не одно окно

Аргумент против суток в `VERDICT-SCALP-5PCT.md` — арифметика на допущении «40 % ночных
сделок чуть хуже», не измерение. Данных о работе наших сетапов вне 16:30–19:30 не было,
потому что вне окна `propose` не вызывался. Теперь каждая ACCORD-идея в любом часу даёт
бумажную сделку с меткой окна, и калибратор (`champion/calibrate.py`) считает Wilson-ДИ
по классу `idea|CAV|ZLG|window|group`. Окно, закрытое в yaml, само не откроется: при
n ≥ 40 и нижней границе ДИ выше break-even оно попадает в `eligible_windows`
(консоль `/api/sessions`), решение — за человеком.

## 3. Что делает размер, стоп и бюджет

- **Размер.** `size_mult` окна берётся минимумом с множителями карточки B, MacroRules и
  ОКО (`strategy_bounce.propose`). Дрейф окна (Page-Hinkley на серии убытков окна, n ≥ 30)
  режет окно ещё ×0,5 до команды `drift_release`. Сайзинг считает от
  `participating_share × equity` (`RiskConfig.participating_share`).
- **Стоп** (`exec/smart_stop.py`): структура (за зоной/фитилём) + буфер
  `max(tick, k_atr·ATR, 3·спред)` с `k_atr` окна, расширенный калибровкой по MAE
  выигрышных бумажных сделок (p90, n ≥ 30, только шире); магниты — круглые числа, края
  соседних зон и **кластеры ликвидаций** из `allLiquidation` (p90 по объёму, ≥ 20 строк);
  потолок `max_stop_atr` (2,5 ATR): дальше — отказ от сделки, не подгонка. Режим
  `manual_bounded`: доля цены от оператора, не ближе авто-стопа и не дальше потолка.
- **Бюджет.** Ключ `YYYY-MM-DD:window`, потолок окна из yaml, глобальный потолок
  `max_intents_per_session` (8). Позиций одновременно до 3, по одной на корреляционную
  группу (`infra/corr_groups.yaml` + скользящая ρ доходностей 4h за 30 дней ≥ 0,8).
- **EV-гейт.** Ожидаемое удержание — медиана бумажных сделок класса `idea|window`
  (n ≥ 30), иначе 2 ч; интервал фандинга — живой.

## 4. Демо-площадка

`demo` в шлюзе = **Bybit Demo Trading** (`api-demo.bybit.com`, `stream-demo.bybit.com`,
pybit `demo=True`): данные mainnet, средства симулированные. Testnet оставлен как
legacy-режим, но его цены не совпадают с mainnet-лентой рекордера, поэтому статистика
демо на testnet ничего не говорит о решениях стола. Ограничения демо учтены: ордера
только REST (так и было), ордера живут 7 дней (журнал — источник истины), триггер
стопа только MarkPrice.

## 5. Консоль

- `GET /api/sessions` — политика, текущее окно, бюджет дня по окнам, бумага по окнам,
  `k_atr_calibrated`, `eligible_windows`, `calibration`, `correlation`, `window_drift`.
- `GET /api/universe`, `POST /api/universe {proposal_id, ack}` — еженедельное
  предложение топ-N по обороту (signer), применяется человеком, вступает в силу после
  рестарта стола/рекордера.
- `GET /api/preview?touch_id=` — вход, стоп и его слагаемые, цель, qty, плечо, риск,
  EV, калибровка, вердикт сессии — из строки журнала, без пересчёта.
- `POST /api/command {kind: drift_release, symbol: <окно>|ALL}`.
- `POST /api/risk` — `participating_share`, `max_stop_atr`, `manual_stop_frac`,
  `stop_mode` (в т.ч. `manual_bounded`), `corr_block_threshold`, `max_open_positions`.

## 6. Критерий перехода демо → реал (составной)

≥ 300 закрытых демо-сделок **и** ≥ 14 календарных дней с одними выходными **и** два
режима волатильности за период **и** на уровне ячеек окна — n ≥ 40 с нижней границей
Wilson выше break-even. Реал открывается только таким ячейкам; остальные продолжают демо
и тень. При потолке ~21 интент/день и прохождении гейтов 30–50 % ожидаемая частота
6–10 сделок/день → 300 сделок за 30–50 дней. Быстрее — только больше символов, не
слабее фильтры.

## 7. Чего здесь нет намеренно

Нет ML-модели входа (Accord-or-Silence остаётся), нет автопродвижения окон и классов,
нет повышения плеча за «A+» (берётся базовое), нет торговли фандинг-таймстампом,
нет CME-гэпа (его больше нет), нет «азиатской ночной премии» (после ETF исчезла).
