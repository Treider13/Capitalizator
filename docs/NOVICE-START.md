# С нуля: Ubuntu-ноутбук + VPS на SpaceWeb

**Для кого:** у вас Linux Ubuntu дома, сервер заказан или заказывается на [SpaceWeb](https://sweb.ru/vds/).  
**Канон команд:** [`VPS-DEPLOY.md`](VPS-DEPLOY.md), [`SESSIONS.md`](SESSIONS.md), [`PLAN-20-DAYS.md`](PLAN-20-DAYS.md).  
**Эта страница не меняет ядро.** Только куда нажать и в каком порядке.

Панель SpaceWeb и пользователь `root` / `trader` на сервере — разные вещи. Логин от [cp.sweb.ru](https://cp.sweb.ru) в операционную систему не пускает.

---

## Что получится

На VPS круглосуточно работают процессы:

| Процесс | Простыми словами |
|---|---|
| `recorder` | Пишет живую ленту Bybit (цены, сделки, стакан) |
| `desk` | Стол: зоны, книга, ОКО, жюри. **В интернет сам не ходит** |
| `signer` | Единственный, кто видит ключ биржи и может поставить ордер |
| `console` | Панель в браузере. С улицы её нет — только туннель с ноутбука |
| `night` | Раз в сутки в 00:30 UTC — отчёт и экзамен |

Первые дни **живыми деньгами никто не торгует**. Стол пишет ленту и бумажный журнал. Учебный счёт Bybit — позже. Реальные деньги — ещё позже и только руками.

---

## Словарь

| Слово | Что это |
|---|---|
| **VPS** | Арендованный сервер. Работает, когда ноутбук закрыт |
| **Панель SpaceWeb** | Сайт [cp.sweb.ru](https://cp.sweb.ru): заказ, IP, пароль, VNC. Это не стол |
| **SSH** | Вход на сервер из терминала Ubuntu |
| **Ключ SSH** | Пара файлов на ноутбуке вместо пароля. Публичный отдаёте серверу |
| **Туннель** | SSH держит трубу: браузер думает, что панель на ноутбуке |
| **Лента** | Сырые тики биржи. Без ленты стол слепой |
| **Контур** | «Стол смотрит зоны». Включать после суток чистой ленты |
| **hello** | Проверка ключа и пробный ордер. Без него demo/live не включатся |
| **learn** | Учёба: тень пишет «вошёл бы», ордеров нет |
| **demo** | **Bybit Demo Trading**: живые цены, фейковые деньги |
| **testnet** | Другая учебная биржа, цены не как у ленты. Не брать |
| **live** | Реальные деньги. Не в первые недели |
| **UTC** | Время сервера. Москва = UTC+3 |

## Часть 0. Ноутбук Ubuntu

Откройте «Терминал» (или `Ctrl+Alt+T`).

Проверьте, что SSH есть:

```bash
ssh -V
```

Если «команда не найдена»:

```bash
sudo apt update
sudo apt install -y openssh-client curl
```

### 0.1. Сделать SSH-ключ (один раз)

```bash
ssh-keygen -t ed25519 -C "ubuntu-ноутбук"
```

На вопросы «куда сохранить» и пароль можно нажать Enter (путь по умолчанию) или задать пароль на ключ — так безопаснее.

Показать **публичный** ключ (эту строку будете копировать):

```bash
cat ~/.ssh/id_ed25519.pub
```

Должно начаться с `ssh-ed25519 AAAA...`.  
Файл `~/.ssh/id_ed25519` **без** `.pub` — секретный. Никому не отправляйте и не кладите в чат.

### 0.2. Узнать домашний IP

Сервер потом пустит SSH только с этого адреса.

```bash
curl -s ifconfig.me; echo
```

Или в браузере: <https://ifconfig.me>.

Если дома IP плывёт (мобильный интернет) — после смены вы не зайдёте, пока не поправите файрвол на сервере. Удобнее проводной интернет.

Запишите IP на бумагу. Он понадобится в `install.sh`.

## Часть 1. Заказать VPS на SpaceWeb

Это **не обычный хостинг сайтов**. Нужен именно **VPS / VDS** с root. На обычном хостинге SpaceWeb root нет — стол туда не поставить.

1. Зайдите в [sweb.ru](https://sweb.ru/vds/) или в уже свою панель [cp.sweb.ru](https://cp.sweb.ru).
2. Раздел **VPS / Виртуальные серверы** → заказать.
3. **Где стоит сервер.** Для Bybit лучше **Амстердам** (линейка «Зарубежные VPS», дата-центр EUnetworks). Москва и Питер ближе к дому, но до движка Bybit дальше, иногда API режется. Если сервер уже в Москве — не паникуйте: на шаге 2.3 проверите `curl`. Если не `200` — нужен Амстердам, а не «торговать с ноутбука».
4. **Система:** Ubuntu **24.04** или **26.04** LTS.
5. **Панель на сервере не ставить.** Не выбирайте ispmanager, Hestia, FASTPANEL, BrainyCP. Нужна голая Ubuntu. Наш стол живёт в Docker, чужая панель только мешает.
6. **Размер.** Минимум **2 ядра, 4 ГБ памяти, от 40 ГБ диска**. Тариф «1 ГБ / 15 ГБ» для Docker и ленты тесный.
7. **Вход.** Можно «по паролю» (пароль `root` придёт на почту). Можно сразу загрузить свой публичный ключ из шага 0.1 в разделе **SSH-ключи** / вкладка **Доступ**. Оба варианта нормальны.
8. Дождитесь письма «VPS готов» и статуса «работает» в панели.

После заказа в [cp.sweb.ru](https://cp.sweb.ru):

- **Виртуальные серверы** → ваша машина → **Управление** — скопируйте **IP**. Дальше в командах это `<vps>`.
- Пароль `root` — в письме или **Настройки → Доступ**.
- Если SSH не пускает — **VNC-консоль** в той же карточке: чёрный экран сервера прямо в браузере, без SSH.

Панель SpaceWeb и Ubuntu на сервере — два разных логина. `dronpardon` / логин sweb — только панель.

## Часть 2. Первый вход на голый сервер

На **ноутбуке** Ubuntu:

```bash
ssh root@<vps>
```

Подставьте IP из панели, без угловых скобок. Пример: `ssh root@203.0.113.10`.

В первый раз спросит `Are you sure you want to continue connecting?` — напишите `yes`.  
Если выбран вход по паролю — вставьте пароль `root` из письма (при вводе символы не видны — так и должно).

Сразу смените пароль root:

```bash
passwd
```

Сохраните новый пароль в менеджере паролей, не в файле на рабочем столе.

Проверьте, что **с сервера** видна биржа (нужна строка `200`):

```bash
curl -s -o /dev/null -w 'mainnet %{http_code} %{time_total}s\n' https://api.bybit.com/v5/market/time
curl -s -o /dev/null -w 'testnet %{http_code} %{time_total}s\n' https://api-testnet.bybit.com/v5/market/time
```

Если не `200` — пишите в поддержку SpaceWeb «исходящий HTTPS до api.bybit.com», не начинайте торговлю. Без этого шага стол слепой.

## Часть 3. Установка стола (один раз, от root)

Всё ещё в сессии `root` на сервере. На ноутбуке заранее скопируйте вывод `cat ~/.ssh/id_ed25519.pub` и домашний IP.

На сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/Treider13/Capitalizator/main/infra/deploy/install.sh -o install.sh
bash install.sh "ssh-ed25519 AAAA... ваш_публичный_ключ" <домашний_IP>
```

Первый аргумент — **вся** строка публичного ключа в кавычках. Второй — IP ноутбука из шага 0.2.

Что скрипт делает сам:

- пользователь `trader` (без парольного sudo; для деплоя хватает группы `docker`);
- время **UTC** + chrony (биржа подписывает запросы окном ~5 секунд);
- файрвол UFW: снаружи только SSH и только с вашего домашнего IP;
- fail2ban;
- Docker;
- каталоги `/srv/capitalizator/{app,userdir,backups,logs}`;
- клон кода в `/srv/capitalizator/app`.

Повторный запуск скрипта безопасен.

**Репозиторий частный.** Если видите `clone failed` — с ноутбука, где уже есть доступ к GitHub:

```bash
# на ноутбуке, в папке с клоном Capitalizator
rsync -a --exclude .venv --exclude userdir ./ trader@<vps>:/tmp/capitalizator-upload/
```

Пока `trader` ещё не пускает — заливайте на `root@<vps>:/srv/capitalizator/app/`, затем на сервере:

```bash
chown -R trader:trader /srv/capitalizator/app
bash install.sh
```

**Парольный вход пока не выключайте** — ни командой ниже, ни галочкой «отключить пароль» во вкладке **Доступ** SpaceWeb. Сначала шаг 4.

Вкладка **Доступ** в SpaceWeb при смене типа входа **перезагружает сервер**. После того как стол уже пишет ленту, туда лучше не лезть без нужды.

## Часть 4. Войти как trader с ноутбука

Выйдите из root (`exit`). На ноутбуке:

```bash
ssh -i ~/.ssh/id_ed25519 trader@<vps>
```

Должно пустить **без пароля SpaceWeb**, вы окажетесь в `/home/trader`.

Чтобы не помнить флаги, один раз на ноутбуке:

```bash
mkdir -p ~/.ssh
nano ~/.ssh/config
```

Вставьте (свой IP):

```
Host capital
    HostName <vps>
    User trader
    IdentityFile ~/.ssh/id_ed25519
    LocalForward 8082 127.0.0.1:8082
```

Права:

```bash
chmod 600 ~/.ssh/config
```

Дальше достаточно:

```bash
ssh capital
```

Эта же команда сразу поднимает туннель к панели стола (часть 8). Окно не закрывайте, пока смотрите браузер.

Когда `ssh trader@<vps>` (или `ssh capital`) точно работает, на сервере от **root**:

```bash
CAP_HARDEN=1 bash /root/install.sh
```

Если файл `install.sh` лежит в другой папке — укажите её. Это выключит парольный SSH и вход под `root` по паролю.

После этого:

- вход: только `trader` и ваш ключ;
- VNC в панели SpaceWeb **продолжает работать** (локальная консоль, без SSH) — запасной люк, если что-то сломаете;
- в SpaceWeb можно оставить пароль в карточке, но `ssh root@...` с паролем уже не пустит.

Если `trader` не пускает:

1. ключ не тот — сравните `cat ~/.ssh/id_ed25519.pub` на ноутбуке с тем, что вставили в `install.sh`;
2. домашний IP сменился — зайдите через **VNC** или пока ещё живой `root`, затем:

```bash
ufw allow from <новый_домашний_IP> to any port 22 proto tcp
ufw delete allow from <старый_IP> to any port 22 proto tcp
ufw status
```

3. опечатка в IP сервера.

Где что на диске сервера:

```
/srv/capitalizator/
├── app/        код
├── userdir/    лента, журнал, секреты
├── backups/    копии раз в 6 часов
└── logs/
```

## Часть 5. Ключ Bybit (учебный)

Нужен ключ **Bybit Demo Trading**, не боевой счёт и не testnet.

### 5.1. Галочки до создания ключа

- [ ] Read + Trade
- [ ] **Withdraw выключен**
- [ ] Белый список IP = **только IP VPS из панели SpaceWeb**, не домашний
- [ ] Лучше сабаккаунт / учебный контур, не «все яйца на корне»
- [ ] 2FA на аккаунте Bybit включена

### 5.2. Где взять ключ

1. Bybit в браузере → **Demo Trading**.
2. В учебном контуре создайте API-ключ: Read + Trade, Withdraw off.
3. В белый список IP — **IP сервера** из SpaceWeb.
4. Скопируйте key и secret (secret показывают один раз).

`mode` в нашей системе: **`demo`**.  
Не берите `testnet`: цены не совпадают с лентой рекордера.

Боевой ключ (`live_sub`) сейчас не создавайте.

### 5.3. Куда вставить

Проще после запуска — в панели стола `/settings` (часть 8). Или сразу на сервере под `trader`:

```bash
nano /srv/capitalizator/userdir/secrets/bybit.json
```

Одна строка:

```json
{"api_key": "ВАШ_КЛЮЧ", "api_secret": "ВАШ_СЕКРЕТ", "mode": "demo"}
```

Сохранить в nano: `Ctrl+O`, Enter, `Ctrl+X`. Затем:

```bash
chmod 600 /srv/capitalizator/userdir/secrets/bybit.json
```

Права `600` обязательны. Ключ не в git, не в Telegram, не в чат.

## Часть 6. Список монет

По умолчанию Docker берёт только BTC и ETH (`week0`). Для учёбы на 10 парах нужна строка `CAP_UNIVERSE=desk`.

На сервере под `trader`:

```bash
nano /srv/capitalizator/app/infra/deploy/.env
```

Если файла нет — сначала часть 7 (deploy создаст его), потом допишите и снова `deploy.sh`.

Строка:

```
CAP_UNIVERSE=desk
```

Это BTC, ETH, SOL, XRP, DOGE, BNB, ADA, AVAX, LINK, SUI. Не раздувайте до 20 монет: паспорт у каждой пары свой.

## Часть 7. Запуск стола

Только от `trader`, не от root:

```bash
bash /srv/capitalizator/app/infra/deploy/deploy.sh
```

Скрипт соберёт образ и поднимет процессы. Повторный запуск обновляет код и не трёт данные в `userdir`.

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose ps
```

Живы: `recorder`, `desk`, `signer`, `console`, `night` (и `intel`).  
`desk` / `signer` через минуту-две — `healthy`.

Если Restart по кругу:

```bash
docker compose logs --tail 80 recorder desk signer
```

Торговлю не включайте, пока это не зелёное.

Бэкап раз в 6 часов (один раз):

```bash
( crontab -l 2>/dev/null; echo '0 */6 * * * bash /srv/capitalizator/app/infra/deploy/backup.sh' ) | crontab -
```

В панели SpaceWeb **не открывайте** порт 8082 и не ставьте «сайт на этом IP». Консоль наружу не должна торчать.

## Часть 8. Панель стола в браузере ноутбука

Консоль слушает только `127.0.0.1:8082` **на сервере**.

На ноутбуке отдельное окно, не закрывать:

```bash
ssh -i ~/.ssh/id_ed25519 -L 8082:127.0.0.1:8082 trader@<vps>
```

Или, если сделали `~/.ssh/config` из части 4:

```bash
ssh capital
```

В Firefox / Chrome на Ubuntu:

**http://127.0.0.1:8082**

| Адрес | Зачем |
|---|---|
| `/` | Жив ли стол, режим, касания |
| `/ops` | Управление, риск, ночь |
| `/settings` | Ключ Bybit, если не клали файлом |
| `/touch` | Последнее касание простыми словами |

Кнопки просят галочку **«Подтверждаю»**.

Если ключ ещё не вставлен: `/settings` → «Биржа» → `bybit.api_key`, `bybit.api_secret`, `bybit.mode` = `demo` → сохранить.

## Часть 9. Проверка ключа (hello)

На сервере (сессия `trader`):

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose run --rm signer python -m capitalizator.signer --userdir /data --hello --probe-order
```

Красный hello = ключ, белый список IP или `mode`. Не обходите кнопкой. Режим человека пока **`off`**.

## Часть 10. Сутки ленты → контур → learn

День установки: процессы зелёные, в `/srv/capitalizator/userdir/tape/` растут файлы. Касаний может быть ноль. **Контур выключен.**

Когда на главной оживёт «Включить контур» (`can_enable` — сутки ленты без дыры) — включите и подтвердите.

Потом режим **`learn`**, горизонт **`learn_n_days=20`** (часто по умолчанию 14 — поставьте 20).

Тень пишет «вошёл бы», ордеров нет. Жюри первые дни часто молчит (`SILENCE`) — фильтр работает.

20 дней учёбы считают от **контур on**, не от дня заказа VPS.

## Часть 11. Каждый день 5 минут

На сервере:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose ps
docker compose logs --tail 50 desk recorder night
```

В браузере (туннель открыт): дыры ленты, касания, паспорта.

| Смотреть | Норма | Если плохо |
|---|---|---|
| Процессы | не Restart | логи, не «добавить монеты» |
| Дыры ленты | 0 за сутки | рекордер / сеть SpaceWeb |
| Касания BTC/ETH | не ноль два дня подряд | стол не видит ленту |
| Паспорт растёт к 30 | да | контур off или дыра |
| SILENCE в начале | много | не крутить пороги |
| Ночной exam `passed=false` | мало n | норма первые недели |

Ночь сама в **00:30 UTC** (03:30 МСК).

## Часть 12. Чего не делать

1. Не включать **live** и не писать в `phase.yaml` `trading_mode: "live"`.
2. Не брать testnet вместо Demo Trading.
3. Не крутить `infra/registry.yaml`.
4. Не добавлять кучу монет «набрать 30 быстрее».
5. Не открывать в SpaceWeb порт 8082 «для удобства».
6. Не ставить ispmanager / сайт на этот VPS.
7. Не давать ключу Bybit право Withdraw.
8. Не судить систему по плюсу демо за две недели.
9. Не жать «сменить тип доступа» в SpaceWeb без нужды — сервер перезагрузится и будет дыра в ленте.

## Часть 13. Демо и живые деньги

**Демо** — не в день установки. Сначала hello, живая лента и несколько дней `learn`. В консоли режим `demo`. Пара: стол `demo` ↔ ключ `demo`. `phase.yaml` не трогать.

Тихий день без сделок при SILENCE — норма.

**Живые деньги** по канону: Ф0 = 30 суток ленты; Ф1 = 80 демо-отскоков; Ф4 = 100 live или 8 недель и винрейт ≥ 55%. Четыре замка: ключ `live_sub` → человек пишет `phase.yaml` после гейта Ф4 → кнопка `live` → режимы совпадают.

За 20 дней канонический live не берётся. Честный исход: остаться в `demo`.

## Часть 14. Если сломалось

| Симптом | Куда смотреть | Не делать |
|---|---|---|
| `ssh` не пускает | домашний IP, ключ, UFW; запасной вход — VNC в SpaceWeb | не открывать порт 22 всему интернету насовсем |
| Биржа с сервера не 200 | дата-центр (Москва?), тикет SpaceWeb | не писать ленту с ноутбука «вместо» |
| Контейнер Restart | `docker compose logs` | не включать live |
| Панель не открывается | забыли `ssh capital` / туннель | не публиковать 8082 в SpaceWeb |
| Hello красный | ключ, IP allowlist, `mode` | не обходить |
| Паспорт BTC стоит | рекордер, контур | не добавлять 10 альтов |

Обновить код (как `trader`):

```bash
bash /srv/capitalizator/app/infra/deploy/deploy.sh
```

Перезапуск одного процесса:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose restart signer
```

Перезагрузить саму машину — только из SpaceWeb → **Управление → Перезагрузить**, если зависла. Это дыра в ленте; контур потом снова ждёт сутки без дыры.
