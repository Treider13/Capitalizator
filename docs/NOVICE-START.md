## Что получится в конце

На арендованном компьютере в интернете (это и есть **VPS**) круглосуточно работают пять процессов:

| Процесс | Простыми словами |
|---|---|
| `recorder` | Пишет живую ленту Bybit (цены, сделки, стакан) в файлы |
| `desk` | Стол: зоны, книга, ОКО, жюри. **В интернет сам не ходит** |
| `signer` | Единственный, кто видит ключ биржи и может поставить ордер |
| `console` | Панель в браузере. С улицы её нет — только через туннель |
| `night` | Раз в сутки в 00:30 UTC делает ночной отчёт и экзамен |

Первые дни стол **не торгует живыми деньгами**. Он пишет ленту, учится смотреть и ведёт бумажный журнал. Ордера на учебном счёте Bybit — позже. Реальные деньги — ещё позже и только руками.

## Словарь на одну минуту

| Слово | Что это |
|---|---|
| **VPS** | Арендованный сервер. Работает 24/7, даже когда ноутбук закрыт |
| **SSH** | Безопасный вход на сервер из чёрного окна терминала |
| **Ключ SSH** | Пара файлов на ноутбуке вместо пароля. Публичный отдаёте серверу, секретный никому |
| **Туннель** | SSH держит «трубу»: браузер думает, что панель на вашем компьютере, а она на сервере |
| **Лента (tape)** | Сырые тики биржи. Без ленты стол слепой |
| **Контур** | Переключатель «стол смотрит зоны и пишет решения». Включать только после суток чистой ленты |
| **hello** | Проверка ключа: время, кошелёк, пробный ордер туда-обратно. Без него демо/live не включатся |
| **learn** | Режим учёбы: тень пишет «вошёл бы», ордеров нет |
| **demo** | Учебный счёт **Bybit Demo Trading**: цены как у живого рынка, деньги фейковые |
| **testnet** | Другая учебная биржа. Цены **не** совпадают с лентой. Для статистики не брать |
| **live** | Реальные деньги. Четыре замка. Не в первые недели |
| **UTC** | Мировое время. Москва = UTC+3. Сервер всегда в UTC |

## Часть 0. Что купить и что подготовить дома

### 0.1. Ноутбук

Нужно:

- Windows 10/11, macOS или Linux
- Терминал: на Windows — **PowerShell** или «Терминал»; на Mac — «Терминал»
- Браузер
- Аккаунт Bybit (обычный, с включённой двухфакторкой)

На Windows команда `ssh` уже есть. Проверка:

```powershell
ssh -V
```

Если пишет «не найдено» — в Параметрах Windows включите «OpenSSH Client» (Дополнительные компоненты).

### 0.2. Сделать SSH-ключ на ноутбуке (один раз)

В терминале:

```bash
ssh-keygen -t ed25519 -C "мой-ноутбук"
```

На вопросы «куда сохранить» и «пароль на ключ» можно нажать Enter (путь по умолчанию, без пароля) или задать пароль — так безопаснее.

Показать **публичный** ключ (это длинная строка, её можно копировать):

```bash
# Linux / macOS
cat ~/.ssh/id_ed25519.pub

# Windows PowerShell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

Секретный файл `id_ed25519` **никому не отправляйте** и не кладите в чат.

### 0.3. Узнать свой домашний IP

Сервер потом пустит SSH только с этого адреса (если указать его при установке).

В браузере откройте <https://ifconfig.me> — это ваш текущий IP.  
Или в терминале: `curl -s ifconfig.me`.

Если дома IP плывёт (мобильный интернет, смена роутера) — запомните: после смены IP вы не зайдёте, пока не поправите файрвол на сервере. Стабильнее домашний проводной интернет.

### 0.4. Какой VPS взять

Ориентир (в репозитории нет жёсткого «прайса», это здравый минимум):

- Система: **Ubuntu 24.04** (или 26.04 — как на уже рабочем сервере)
- **2 vCPU, 4 ГБ RAM, от 40 ГБ диска**
- Дата-центр ближе к Азии/Европе, чем к США. Уже проверенный вариант — **Амстердам** (до Bybit около 0.2 с)
- Дают пароль `root` на почту или в панели хостера

Панель хостера (у текущего сервера это HOSTKEY, логин вроде `dronpardon`) — это **не** операционная система. В ОС два пользователя: `root` и потом `trader`.

## Часть 1. Первый вход на голый сервер

В панели хостера найдите **IP сервера**. Дальше `<vps>` = этот IP, например `91.229.105.226`.

С ноутбука:

```bash
ssh root@<vps>
```

В первый раз спросит «trust this host?» — напишите `yes`. Потом пароль `root` из письма хостера.

Сразу смените пароль root:

```bash
passwd
```

Придумайте длинный пароль и сохраните его в менеджере паролей, не в файле на рабочем столе.

Проверьте, что с сервера видна биржа (ожидание: `200`):

```bash
curl -s -o /dev/null -w 'mainnet %{http_code} %{time_total}s\n' https://api.bybit.com/v5/market/time
curl -s -o /dev/null -w 'testnet %{http_code} %{time_total}s\n' https://api-testnet.bybit.com/v5/market/time
```

Если не `200` — чините сеть/файрвол хостера. Без этого шага дальше нет смысла: стол без биржи слепой.

## Часть 2. Установка (один раз, от root)

На **сервере**, всё ещё под `root`. Подставьте **свой** публичный SSH-ключ целиком (одна строка `ssh-ed25519 AAAA...`) и IP ноутбука:

```bash
curl -fsSL https://raw.githubusercontent.com/Treider13/Capitalizator/main/infra/deploy/install.sh -o install.sh
bash install.sh "ssh-ed25519 AAAA... ваш_публичный_ключ" <IP_вашего_ноутбука>
```

Что скрипт делает сам:

- пользователь `trader` (без парольного sudo; для деплоя хватает группы `docker`)
- время **UTC** + chrony (биржа подписывает запросы окном ~5 секунд — часы должны быть точными)
- файрвол UFW: снаружи только SSH, и только с вашего IP
- fail2ban (банит тех, кто подбирает пароль)
- Docker
- каталоги `/srv/capitalizator/{app,userdir,backups,logs}`
- клон репозитория в `/srv/capitalizator/app`

Повторный запуск скрипта безопасен.

**Репозиторий частный.** Если `clone failed` — с ноутбука, где уже есть доступ к GitHub, залейте код на сервер (или положите deploy-ключ) и запустите `install.sh` ещё раз. Скрипт это сам подсказывает.

**Парольный вход пока не выключайте.** Сначала убедитесь, что вход по ключу работает (часть 3). Потом, уже когда `ssh trader@<vps>` заходит без пароля:

```bash
CAP_HARDEN=1 bash install.sh
```

Это выключит пароль и вход под `root`. Если сделать раньше — можно запереться снаружи.

## Часть 3. Войти на сервер в первый раз

**Закройте** сессию root. С ноутбука:

```bash
# Linux / macOS
ssh -i ~/.ssh/id_ed25519 trader@<vps>

# Windows PowerShell (если ключ по умолчанию)
ssh trader@<vps>
```

Должно пустить **без пароля**, вы окажетесь в домашней папке `trader`.

Если не пускает:

1. ключ не тот (сравните `cat ~/.ssh/id_ed25519.pub` с тем, что вставили в install);
2. ваш домашний IP сменился — зайдите пока как `root` с панели/пароля и добавьте новый IP в UFW;
3. опечатка в IP сервера.

Где что лежит на диске:

```
/srv/capitalizator/
├── app/        код (git)
├── userdir/    живые данные стола: лента, журнал, секреты
├── backups/    копии knowledge раз в 6 часов
└── logs/
```

## Часть 4. Ключ биржи (учебный, не боевой)

Нужен ключ **Bybit Demo Trading**, не ключ основного боевого счёта и не testnet.

### 4.1. Чеклист до создания ключа

Печатайте галочки себе на бумаге ([`ops/key-checklist.md`](../ops/key-checklist.md)):

- [ ] Это **сабаккаунт** или отдельный учебный контур, не «все яйца на корне»
- [ ] Права **Read + Trade**
- [ ] **Withdraw выключен** (вывод денег через API невозможен)
- [ ] IP-белый список = **только IP VPS** (не домашний IP)
- [ ] На корневом аккаунте API лучше не держать
- [ ] 2FA на аккаунте включена

### 4.2. Где взять ключ Demo Trading

1. Войдите в Bybit в браузере.
2. Откройте **Demo Trading** (учебный счёт с фейковыми деньгами и **живыми** ценами mainnet).
3. В этом учебном контуре создайте API-ключ: Read + Trade, Withdraw off.
4. В белый список IP впишите **IP сервера**, не ноутбука.
5. Скопируйте key и secret. Secret показывают один раз.

`mode` ключа в нашей системе должен быть **`demo`**.  
Не берите `testnet`: цены testnet не совпадают с лентой, которую пишет рекордер, и статистика будет врать.

Боевой ключ (`live_sub`) на этом шаге **не создавайте**.

### 4.3. Куда вставить ключ

Два равноправных способа. Проще — через панель после запуска (часть 6–7). Если хотите сразу файлом, на сервере под `trader`:

```bash
nano /srv/capitalizator/userdir/secrets/bybit.json
```

Вставьте **одну** строку (свои значения, не эти точки):

```json
{"api_key": "ВАШ_КЛЮЧ", "api_secret": "ВАШ_СЕКРЕТ", "mode": "demo"}
```

Сохраните (в nano: Ctrl+O, Enter, Ctrl+X) и закройте доступ всем кроме вас:

```bash
chmod 600 /srv/capitalizator/userdir/secrets/bybit.json
```

Права **0600** обязательны. Иначе сигнер ключ не возьмёт.

Альтернатива — файл `/srv/capitalizator/app/infra/deploy/.env` (создастся при первом `deploy.sh`). Имена переменных: `BYBIT_API_KEY`, `BYBIT_API_SECRET`, `BYBIT_MODE=demo`. Файл в панели консоли **побеждает** `.env`, если оба заполнены.

Ключ **не** коммитить в git, не слать в Telegram, не класть в чат с ассистентом.

## Часть 5. Вселенная символов

По умолчанию в Docker стоит `CAP_UNIVERSE=week0` (только BTC и ETH).  
Для нормальной учёбы на 10 перпах поставьте `desk` (список в `infra/universe.yaml`: BTC, ETH, SOL, XRP, DOGE, BNB, ADA, AVAX, LINK, SUI).

На сервере под `trader`:

```bash
nano /srv/capitalizator/app/infra/deploy/.env
```

Если файла ещё нет — сначала часть 6 (deploy создаст его из шаблона), потом вернитесь и допишите строку:

```
CAP_UNIVERSE=desk
```

Сохраните. После смены снова запустите `deploy.sh` (часть 6).

Не раздувайте список до 20 монет в первые недели: паспорт ОКО у каждой пары свой, новый символ стартует с нуля и BTC не «созревает» от SOL.

## Часть 6. Первый запуск стола

На сервере, **обязательно от пользователя `trader`** (не от root):

```bash
bash /srv/capitalizator/app/infra/deploy/deploy.sh
```

Скрипт соберёт образ Docker, поднимет процессы, покажет таблицу `ps`.  
Повторный запуск = обновить код (`git pull`) и перезапустить то, что изменилось. **Данные в `userdir` не трёт.**

Проверка:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose ps
```

Должны быть живы как минимум `recorder`, `desk`, `signer`, `console`, `night` (плюс `intel`).  
`desk` и `signer` в колонке здоровья — `healthy` (не сразу, через минуту-две).

Если контейнер в цикле Restart — смотрите логи, не включайте торговлю:

```bash
docker compose logs --tail 80 recorder desk signer
```

Бэкап раз в 6 часов (один раз настроить):

```bash
( crontab -l 2>/dev/null; echo '0 */6 * * * bash /srv/capitalizator/app/infra/deploy/backup.sh' ) | crontab -
```

## Часть 7. Открыть панель в браузере

Консоль слушает **только** `127.0.0.1:8082` на сервере. В интернет порт не торчит. Это специально.

На **ноутбуке** откройте отдельное окно и **не закрывайте его**, пока смотрите панель:

```bash
ssh -i ~/.ssh/id_ed25519 -L 8082:127.0.0.1:8082 trader@<vps>
```

В браузере ноутбука:

**http://127.0.0.1:8082**

| Адрес | Зачем новичку |
|---|---|
| `/` | Стол: живо ли, режим, символы, касания, «входы заблокированы» |
| `/ops` | Управление: пауза, риск, сессии, ночь, экзамен |
| `/settings` | Сюда вставлять ключ Bybit, если не клали файлом |
| `/touch` | Последнее касание зоны простыми словами |

Все кнопки, которые что-то меняют, просят галочку **«Подтверждаю»**. Это защита: чужой сайт не отправит команду от вашего имени.

Если ключ ещё не вставлен: `/settings` → группа «Биржа» → `bybit.api_key`, `bybit.api_secret`, `bybit.mode` = `demo` → сохранить группу.

## Часть 8. Проверка ключа (hello)

Пока hello не зелёный, консоль **откажется** включить `demo` или `live`. Стол ордера и так не шлёт.

На сервере:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose run --rm signer python -m capitalizator.signer --userdir /data --hello --probe-order
```

Команда проверяет время, кошелёк, позиции, комиссии, инструменты и ставит/снимает пробный ордер.

Красный hello = ключ, IP-белый список, или `mode` не тот. **Не обходите** это кнопкой в консоли. Исправьте ключ и повторите.

Режим человека (`user_mode`) пока оставьте **`off`**. Не ставьте `demo`, пока hello не прошёл.

## Часть 9. Сутки ленты, потом контур и учёба

### 9.1. День установки — только смотреть

Ожидание к вечеру первого дня:

- процессы зелёные;
- в `/srv/capitalizator/userdir/tape/` появляются файлы;
- касаний зоны может быть ноль — это нормально;
- **контур ещё выключен**.

Канон: контур включают, когда консоль показывает `can_enable` = сутки ленты **без дыры**. Если включить раньше — решения будут на дырявых данных.

### 9.2. Когда кнопка «Включить контур» оживёт

На главной панели блок «Контур». Кнопка активна только при `can_enable`. Нажмите, подтвердите.

Контур **не** пишет файл `infra/phase.yaml`. Это только «стол смотрит».

### 9.3. Режим learn на 20 дней

Там же режим человека: **`learn`**, горизонт **`learn_n_days=20`** (в интерфейсе по умолчанию часто 14 — для этого старта поставьте 20), галочка подтверждения.

Что происходит:

- тень, фейд и претендент пишут бумажные сделки **круглосуточно** в любом режиме;
- **ордеров на биржу нет**;
- жюри первые дни часто молчит (`SILENCE`) — это успех фильтра, не поломка.

20 дней учёбы считают от **контур on**, не от дня, когда вы склонировали репозиторий. Дыра в ленте сдвигает календарь.

## Часть 10. Каждый день 5 минут (не настраивать, смотреть)

На сервере:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose ps
docker compose logs --tail 50 desk recorder night
```

В браузере (туннель открыт): главная → блок «Учёба», дыры ленты, число касаний.

| Смотреть | Зелёный ориентир | Если плохо |
|---|---|---|
| Процессы | не Restart loop | логи, не «добавить монеты» |
| Дыры ленты | 0 за сутки | чинить рекордер/сеть |
| Касания BTC/ETH | не ноль два дня подряд | стол не видит parquet |
| Паспорт n | растёт к 30 | тихий стол = дыра или контур off |
| Жюри SILENCE | в начале много | не ослаблять пороги |
| Ночной exam | `passed=false` из‑за малого n | норма недели две |
| Краны дня/недели | на learn не должны стрелять | если стреляют — читать причину |

Ночной контур сам в **00:30 UTC** (03:30 МСК). Вручную, если пропуск:

```bash
docker compose run --rm night python -m capitalizator.ops.night --userdir /data --day ГГГГ-ММ-ДД
```

Дата — тот день, который разбираете (обычно вчера по UTC).

## Часть 11. Что нельзя делать в первые недели

Это не «советы», а то, из‑за чего потом нельзя честно сказать, что стол проверен:

1. Не включать **`live`** и не писать в `infra/phase.yaml` строку `trading_mode: "live"`.
2. Не ставить **override** «ну просто проверить».
3. Не брать ключ **testnet** для статистики и не путать его с Demo Trading.
4. Не крутить пороги в `infra/registry.yaml` «чтобы чаще входило».
5. Не добавлять 10 новых монет, чтобы «быстрее набрать 30».
6. Не открывать ночное окно в `sessions.yaml` и не включать пробои (`breakout_enabled`), пока лестница гейтов не дошла до этого.
7. Не повышать размер позиции и не усредняться (`average_in`).
8. Не выкладывать консоль в интернет (`0.0.0.0`, проброс 8082 на хостере).
9. Не класть ключ с правом **Withdraw**.
10. Не судить систему по плюсу/минусу демо за две недели: сделок мало, один режим рынка.

## Часть 12. Когда включать демо (фейковые деньги, живые цены)

Не в день установки. Ориентир плана: после hello, живой ленты и нескольких дней `learn` (в календаре плана это около дня 19 от **контур on**). Раньше — только если хотите проверить «ордер доходит», понимая, что статистики ещё нет.

В консоли: режим **`demo`**, подтвердить.

Нужны одновременно:

- hello зелёный;
- ключ с `mode: demo`;
- режим стола `demo` (пара: стол `demo` ↔ ключ `demo` или устаревший `testnet`; стол `live` ↔ ключ `live_sub` / `live_main`).

`phase.yaml` для демо в `live` **не** переключают. Он должен остаться как есть (`trading_mode: "off"`).

Что увидеть:

- если жюри сказало ACCORD и окно сессии открыто — интент уходит в signer, на учебном счёте появляется ордер;
- если день тихий (SILENCE) — **ноль сделок нормален**. Не переключайте в live «чтобы проверить трубу».

Сверьте одну бумажную тень и одну демо-сделку на том же касании. Большое расхождение — баг трубы, не «рынок виноват».

## Часть 13. Когда (и когда нет) живые деньги

Полноценный канон из гейтов продукта:

| Гейт | Что должно быть | Грубо по времени |
|---|---|---|
| Ф0 | 30 суток ленты BTC+ETH без дыр | месяц ленты |
| Ф1 | 80 закрытых демо-отскоков, средний R > 0 | ещё недели после Ф0 |
| Ф4 | 100 live **или** 8 недель (что позже), винрейт ≥ 55% | месяцы |

Четыре замка live (все сразу):

1. Ключ **`live_sub`** (сабаккаунт, Read+Trade, без Withdraw, IP = VPS).
2. Человек сам пишет `infra/phase.yaml`: `trading_mode: "live"` — **после** зелёного `python -m capitalizator.ops.gates f4`. Бот этот файл не трогает.
3. В консоли режим `live` + подтверждение. Без hello — отказ.
4. Пара режимов совпадает (см. часть 12).

За 20 дней календарного плана канонический live **не берётся**. Честный исход дня 20: остаться в `demo`.  
Микро-live с текстом-причиной — только как проверка маршрута ордера, крошечным размером, по чеклисту в [`PLAN-20-DAYS.md`](PLAN-20-DAYS.md) §5. Если любого пункта нет — остаёмся в демо.

## Часть 14. Если что-то сломалось

| Симптом | Куда смотреть | Не делать |
|---|---|---|
| `ssh` не пускает | IP дома сменился, ключ, UFW | не открывать 22 всему миру насовсем |
| Биржа с сервера не 200 | сеть хостера, DNS | не торговать «с ноутбука вместо ленты» |
| Контейнер Restart | `docker compose logs` | не включать live |
| Панель не открывается | туннель закрыт, опечатка 8082 | не публиковать порт на хостере |
| Hello красный | ключ, IP allowlist, `mode` | не обходить HelloRequired |
| Режим ≠ ключ | в Настройках `bybit.mode` | не слать live-ключом в demo |
| Паспорт BTC не растёт | рекордер пишет ли BTC, контур on? | не добавлять 10 альтов |
| 0 строк в журнале | контур off или нет печати в зоне | не крутить registry |
| Входы заблокированы | пульс стола, сверка, кран | `release_signer` только если поняли причину |

Обновление кода (как `trader`):

```bash
bash /srv/capitalizator/app/infra/deploy/deploy.sh
```

Перезапуск одного процесса:

```bash
cd /srv/capitalizator/app/infra/deploy
docker compose restart signer
```
