# Изобретение: жюри графика и процент во времени

**Дата:** 30.08.2026, ночь.  
**Зачем эта записка.** Ты сказал прямо: смысл стола — **максимум аналитики и грамотное решение**. График и свечи должны **взвешиваться**, не стоять декорацией рядом со стаканом. И нужны **наши** алгоритмы, которых нет у автоторговли на перпах. Цель гонки — не самая большая сумма на счёте, а **заработанный процент за минимальное честное время**.

Это не отмена жеста книги и не «стратегия на свечках». Свечи без книги по-прежнему запрещены (`PHASE-BUILD`). Книга без свечи — тоже не стол. Решение принимает **жюри**, не один канал.

Деньги и фазы не переписываем. 900k по-прежнему хвост после гейта. Усреднения нет.

## 0. Одной фразой

Мы изобретаем не «ещё один паттерн». Мы изобретаем три связанных алгоритма, которых **нет как живого продукта на крипто-перпах**:

1. **Свечной аккорд (CAV)** — четыре метки графика, привязанные к *нашей* зоне, в ту же секунду, что жест книги.  
2. **Стол присяжных (WJD)** — все каналы всегда считаются; сделка только при **согласии**, не при среднем из спорящих.  
3. **Граница процента во времени (PTF)** — оптимизируем **% за час нашей сессии**, не рубли и не число сделок.

Первые по сумме не будем. Первые по «наш % / наш час после таблицы согласия» — единственная гонка, где финиш ещё пустой. Это и есть «лучшие в процентах за короткий срок» без сказки.

## 2. Алгоритм 1. Свечной аккорд (CAV)

**Имя:** Candle Accord Vector.  
**Что это.** В момент касания зоны \(Z\) код ставит **одну** метку графика. Не «молот», не FVG, не 缠论-中枢. Четыре вопроса к *нашим* свечам на рабочем ТФ плюс старший.

| Метка | Что видит график | Черновая гипотеза (ещё не наша частота) |
|---|---|---|
| **REJECT** | Фитиль ушёл в зону / сквозь край, **закрытие рабочей свечи вернулось внутрь** своей стороны | Зону отстояли телом. Кандидат отскок |
| **THROUGH** | **Закрытие** рабочей свечи за зоной по направлению удара | Закрепились. Кандидат пробой (ещё нужны лента и BTC) |
| **COMPRESS** | Диапазон последней закрытой < \(k\cdot\mathrm{ATR}\) у края зоны, закрытие внутри | Сжатие у стены. Ждём жест; сами не стреляем |
| **DRIFT** | Цена в зоне, тела мелкие, нет ни отказа, ни закрытия за | Касание без решения графика. Часто шум |
| **NOISE** | Незакрытая свеча, или первая минута после выноса, или старший ТФ против | График ещё не имеет права голоса |

**Жёсткие куски (уже наши законы, теперь в метке)**

- THROUGH **нельзя** поставить по незакрытой свече. Corbet: минутный «купи пробой» на BTC в минусе.  
- REJECT нельзя поставить по одному фитилю без закрытия. Фитиль сам = шум (`SR-LEVELS-SCIENCE`).  
- Старший ТФ (H4/D1) владеет стороной. Если он против — метка **NOISE**, не «локальный REJECT важнее».  
- Метка привязана к `zone_id`. Тот же молот в середине диапазона — **не CAV**. Середина не торгуется.

**Почему этого нет у автоторговли.**  
ICT / SMC / 缠论 рисуют геометрию свечи **после факта** и зовут её сигналом. Свечные боты (Freqtrade, Haehnchen) жгут RSI/MACD **без нашей зоны**. Стаканные боты (сетки, MM) свечу игнорируют.  
Пустое пересечение: **метка закрытой свечи × заранее построенная зона × тот же timestamp, что ZLG**. Этого репозитория нет. WORLD-SEARCH это подтвердил на CN/IN/JP/KR.

**Пример.** 17:08. SOL зона 148.2–149.0. 15-минутка закрылась: низ 148.15, close 148.72. Старший час выше своей зоны. CAV = **REJECT**.  
Рядом книга за 6 с: DEFEND. Это не «два индикатора купили». Это два независимых голоса про одну зону.

Другой день. Та же зона, фитиль 147.90, close 147.80 — тело за зоной. CAV = **THROUGH**. Жест DEFEND здесь **не** открывает лонг-отскок: график уже сказал «закрылись ниже». Жюри обязано замолчать или перейти в карточку пробоя, не усреднять голоса.

## 3. Алгоритм 2. Стол присяжных (WJD)

**Имя:** Weighted Jury Desk.  
**Смысл «максимум аналитики».** Все пять ролей **всегда** считают свой голос. График не «если останется время». Новость не «вместо свечи». Решение — не среднее спорящих.

Каждый канал в момент касания даёт одно из четырёх:

| Голос | Значение |
|---|---|
| **+1** | За сторону идеи (лонг отскок / шорт отскок / пробой по направлению) |
| **−1** | Против стороны идеи |
| **0** | Не знает / мало n / канал ещё не созрел |
| **VETO** | Запрет. Сделка мертва независимо от остальных |

| Канал | Откуда +1 / −1 | Когда VETO | Когда 0 |
|---|---|---|---|
| **CAV** (график) | REJECT с нами / THROUGH против отскока | NOISE на первой минуте выноса, если хотим пробой | DRIFT, COMPRESS, n < 20 на метку |
| **ZLG** (книга) | DEFEND/IMPROVE с отскоком; RETREAT с пробоем | SILENCE | n < 20 на жест |
| **Tape** | не едят (отскок) / едят (пробой) | стена без печати, если хотим «держать» | мало сделок в окне |
| **BTC** | бокс или в ту же сторону | слом против альта | BTC сам в DRIFT |
| **Card** | несущие VERIFIED | REFUTED / UNVERIFIABLE на несущем / CPI-окно | карточка черновик (Ф0–1) |

**Правило согласия (Accord-or-Silence)**

```
есть хоть один VETO     → skip
CAV и ZLG оба 0         → skip   (график и книга молчат — аналитики нет)
CAV и ZLG разных знаков → skip   (не усредняем свечу со стаканом)
есть −1 при живом +1    → skip
есть −1 без +1          → skip   (возражение без факта за — тоже спор)
+1 у факта книги        → кандидат (ZLG, ОКО или лента на пробое; голый график — молчание)
риск не подписал        → skip
```

Уточнение 2026-09-03 (`jury/desk.py`): голоса делятся на **факты** (свеча CAV, книга ZLG, ОКО,
лента на пробое — могут сказать +1/−1/VETO) и **фильтры** (лента на отскоке, BTC, карточка —
только VETO/−1/0). «Стену не съели», «BTC в боксе», «карточка предлагает» — отсутствие плохого
знака, не голос за. Вход открывает только +1 факта книги; CAV подтверждает, но один не входит.

Это **не** ансамбль «RSI 40% + MACD 30% + книга 30%». Спорящие каналы **не** получают сделку. Молчание — успех дня, не простой. Доска спасённых R это уже умеет считать.

**Веса — из нашей памяти, не из вкуса**

Пока \(n\) метки < 20, веса **равны** и всё равно требуется согласие. Мы не «верим книге больше, потому что изобрели жест».

После экзамена контура C (раз в 15–20 дней) вес канала \(i\):

\[
w_i = \frac{n_i}{n_i+\kappa}\cdot \mathrm{hit}_i
\]

\(\mathrm{hit}_i\) — как часто этот канал был прав *в наших* эпизодах, когда он дал ненулевой голос. \(\kappa\) большое на старте. Вес **не** открывает сделку в одиночку. Вес только **ранжирует** уже согласованные классы (какой тип согласия кормит лучше). ИИ вес не ставит.

**Почему этого нет.** TradingAgents спорит и **не** шлёт ордер. Freqtrade усредняет индикаторы. howtrader ждёт webhook. 缠论 и ICT — один канал (свеча).  
Пустой продукт: **пять голосов × запрет среднего × веса из нашего журнала × живой перп**.

**Пример грамотного отказа.**  
Зона красивая. CAV = REJECT. Жест = RETREAT. Лента не ест. BTC в боксе. Карточка зелёная.  
Старый «умный бот» купил бы «потому что зона+BTC+новость».  
Жюри: CAV +1, ZLG −1 → **split → skip**. В реестр пишем `jury=SPLIT, saved_r=…`. Через 40 таких строк мы *узнаем*, кто из двоих врёт чаще. Пока не узнали — размера нет.

**Пример входа.**  
CAV REJECT, ZLG DEFEND, tape не ест, BTC бокс, 5 VERIFIED. `jury=ACCORD`. Первый факт по-прежнему жест (быстрее всех). График **подтвердил**, не заменил. Размер — от зрелости *обоих* n, не от «ИИ уверен».

## 4. Алгоритм 3. Граница процента во времени (PTF)

**Имя:** Percent-Time Frontier.  
**Смысл «лучшие в процентах за короткий срок».**  
Самая большая сумма на фьючах занята. Самый большой % за полгода среди людей — порядка WSOT **+37% / 6 мес** (Saxo, не наш рынок). Мы **не** подписываем «обгоним это в ноябре». Мы подписываем **другую** гонку, которой нет как продукта:

> среди *наших* согласованных классов выбрать тот, у которого выше **ожидаемый % счёта за час окна 16:30–19:30 МСК**, и торговать только его.

Метрика класса \(C\) (например `bounce × REJECT × DEFEND × BTC_box`):

\[
\rho_C = \frac{\mathbb{E}[R_C]\cdot r_{\%}}{H}
\]

- \(\mathbb{E}[R_C]\) — средний R класса из **нашего** реестра;  
- \(r_{\%}\) — риск счёта на сделку (1% до гейта, ≈1.2% после);  
- \(H\) — часы сессии, которые этот класс реально занял (не календарные сутки).

Окно у нас **3 часа**, не 24. «Короткий срок» = каждый час сессии должен кормить, а не «15 тейкер-сделок в сутки» (тот путь уже убит: медиана месяца ~86k).

**Что PTF делает**

- Сортирует классы согласия по \(\rho\), не по числу сделок и не по «красивой зоне».  
- Низкий \(\rho\) при живом WR — класс выключаем: он ест время сессии.  
- Высокий \(\rho\) при широком ДИ — ещё не включаем: короткий срок без таблицы = ложь.  
- После гейта цель дня — **2 A+ из лучших \(\rho\)**, не «набрать оборот». Третья — только стол 5/5.

**Что PTF нарочно не делает**

- Не обещает мировой рекорд % за неделю.  
- Не поднимает риск, чтобы \(\rho\) вырос на бумаге.  
- Не включает сутки и сетку «чтобы процент быстрее».  
- Не меняет 900k-математику: без края \(\rho\) честно около нуля, счёт ~100k.

**Почему этого нет.** Гриды максимизируют число fill. ICT не считает % / час сессии. Лидерборды HL — абсолютный PnL людей. Passivbot не знает окна 16:30–19:30.  
Пустой продукт: **таблица \(\rho\) по классам согласия на живых перпах**. Её нельзя скачать. Она растёт только нашими часами.

**Честный потолок (не переоткрываем вердикты)**

| Вопрос | Уже посчитано | Как читает PTF |
|---|---|---|
| % за 6 мес без края | ~0…+10% «без риска» | \(\rho\) ≈ 0, торгуем тень |
| После 57% / 1.2% / 2 A+ | медиана пути ~×8.6 за 6 мес | это *после* гейта, не «с понедельника» |
| Чемпион мира по % / 6 мес | WSOT +37% | другая площадка; не наш титул на старте |
| 10%/день как метод | нет такого занятия | PTF это запрещает тем же законом |

«Максимально короткий срок» = **не ломать фазы**, а **не тратить часы сессии на классы с плохим \(\rho\)**. Гейт ~139 сделок, чтобы отличить 57% от монетки, остаётся. Ускорить можно только качеством: меньше мусора → те же 139 ближе к A+, не ближе к сливу.

## 5. Как три алгоритма стыкуются с первым фактом

Порядок горизонтов **не меняется**:

```
ZLG ~ 8 с  →  лента ~ те же секунды  →  CAV (закрытая свеча, минуты)
     →  BTC (час)  →  автор / новость (часы–сутки)
```

**Первый факт** по-прежнему = самый быстрый *с нашей частотой*. Обычно жест.  
CAV становится первым фактом **только** если рабочая свеча уже закрыта и \(n_{\mathrm{CAV}}\ge 20\). Незакрытый THROUGH первым фактом быть не может.

Жюри **выше** первого факта как замок: даже зрелый DEFEND не откроет лонг, если CAV = THROUGH.  
Первый факт **ниже** жюри как ключ размера: согласие без зрелого быстрого факта → тень или четверть.

ИИ комментирует оба голоса. Не заменяет ни один. Не поднимает \(\rho\).

## 6. Что писать в реестр с фазы 0 (чтобы изобретение жило)

На каждое касание, ещё без сделок:

```
zone_id, touch_ts,
cav_label, cav_tf, htf_side,
zlg_label, tape_eaten,
btc_state,
jury = ACCORD | SPLIT | VETO | SILENCE,
first_fact, n_cav, n_zlg,
outcome = bounce|break|die,   -- когда дозреет
rho_class_id
```

Два прогона одного дня = те же метки. Lookahead запрещён: CAV только из закрытых баров с `close_ts ≤ t`.

Через ~30 дней записи без денег — первая в мире таблица **CAV × ZLG × исход**. Её нет у Osler, нет у czsc, нет у ICT, нет у passivbot.

Гейт в микро не меняется. Добавляется только: жюри детерминировано; SPLIT не торгуется даже на демо, если учим «руки согласию».

## 7. Чего изобретение нарочно не делает

- Не стратегия «на свечках без книги».  
- Не ICT / SMC / 缠论 как вход.  
- Не среднее спорящих индикаторов.  
- Не «обгоним мир по % в ноябре».  
- Не предсказание mid. Не спуфинг. Не доливка.  
- Не подпись Sharpe > 3. Если REJECT×DEFEND = монетка — таблица это покажет, класс умрёт. Изобретение честно умерло лучше, чем живой миф.

## 8. Что меняется в плане

| Меняется | Не меняется |
|---|---|
| Роль 1 получает метку CAV, не только «зону нарисовали» | Пять ролей, три контура, окно 16:30–19:30 |
| Вход только `jury=ACCORD` | Запрет усреднения, 10% = маржа, риск ≈1.2% после гейта |
| Деньги после гейта целимся в лучший \(\rho\), не в оборот | 900k = хвост; без гейта снята |
| Реестр шире: CAV × ZLG × jury × исход | Первый факт по скорости — жест |
| «Лучшие в % за короткий срок» = PTF нашего класса | Первые по абсолютной сумме — нет |

Одной фразой: **график и книга всегда оба говорят; если не согласны — мы умнее молчим; если согласны и таблица жива — мы берём тот класс, который кормит больше процента за час сессии.** Этого автомата на перпах нет. Сумму чемпиона мира он не обещает. Процент за наш час — единственное, что мы имеем право оптимизировать.
