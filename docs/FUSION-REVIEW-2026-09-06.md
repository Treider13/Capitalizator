# Повторная проверка Fusion · 6 сентября 2026

Исторический отчёт PR #45. Последующие дефекты интеграций и их исправления
описаны в [новом аудите](FUSION-CAUSAL-AUDIT-2026-09-06.md).
Результаты ниже относятся к прежней версии, а не заменяют новую проверку.

Проверка относится к `capitalizator.fusion` в PR #45. Это отчёт об исправлениях
программы, а не свидетельство прибыльной торговли. Утверждения «без ошибок»,
«все стратегии мира проверены», «30% каждый месяц» не подтверждены.

## Подтверждённые дефекты и исправления

| Было | Чем установлено | Исправление |
|---|---|---|
| Пополнение стакана обнулялось при SDK-снимках | В установленном pybit 5.17.0 `_websocket_stream.py` присваивает callback `type=snapshot` и отдаёт накопленную книгу; Market считал refill только на delta | Собственный raw public WebSocket поверх websocket-client; настоящие snapshot/delta; приватный SDK и REST сохранены |
| Рыночный обработчик ждал сетевого исполнителя | `Engine._send` и `Executor.tick` использовали один entry_lock | Короткая admission-блокировка отдельно от блокировки сетевой отправки; тест удерживает сетевой lock и проверяет завершение рыночного обработчика |
| Пять секунд могли накапливать неограниченный список принтов | `pending.append` с последующими несколькими полными проходами | OHLCV/дельта/крупнейший принт/объём block trades считаются инкрементально; тест 100 000 принтов без расширения полей аккумулятора |
| 5m строился, но отбрасывался; HTF/LTF не был входным условием | Market сохранял только 1m; propose проверял лишь положение в локальном диапазоне | Закрытые 1m/5m/15m/1h/4h; пары 15m→1m, 1h→5m, 4h→15m; подтверждённые pivots, POI и локальный sweep/reclaim обязательны |
| Произвольный диапазон выдавался за направленный Fibonacci swing | Discount считался по последним торговым блокам | Упорядоченные подтверждённые свинги; направление HH/HL или LH/LL; retracement 0.5–1 и отдельная OTE |
| В интерфейсе не было графика | HTML содержал таблицы/JSON и опрос раз в 3 секунды | Canvas-свечи, SSE, уровни, зоны, профиль, Volume/CVD, сессии, гипотезы и реальные execId; ограничение до 8 SSE-подключений |
| Один источник новостей выглядел как полное покрытие | Единственная отметка news_at обновлялась по объявлениям Bybit | Состояние каждого источника и покрытия каждой монеты; макрокалендарь с контролем исчерпания; официальные RSS/Atom; отдельный адаптер анлоков |
| Gamma всегда None | Поле Market без источника опционных данных | Публичные option tickers Bybit: unsigned gross gamma, концентрация страйков, OI-взвешенная IV и изменения; IV может только уменьшить риск |
| Без модели не проверялась негативная новость для уже открытой позиции | on_block возвращался раньше manage | Управление позицией выполняется и без модели; свежая негативная новость создаёт запрос flatten |
| Старые метки и Demo-результаты могли квалифицировать изменённую архитектуру | Общая таблица samples и общий отчёт Demo | Версия политики в метках и ордерах, отдельная эпоха квалификации, прежняя модель не загружается; изменённый Live остаётся на паузе до новой Demo-квалификации |
| RR считался до издержек | Проверялось только отношение ценовых расстояний | Финальный резерв проверяет RR после консервативных комиссий, спреда и funding |
| Backup обращался к отсутствующему активному сервису desk | `infra/deploy/backup.sh` | Новый online SQLite backup и копирование только архивов из его согласованного манифеста |
| Новая инструкция запуска соседствовала со старой; основной image тянул HYEXEC | README и Dockerfile | Основной README описывает Fusion; старые README/Dockerfile/backup/Compose явно помечены legacy; новый image без HYEXEC |

Это воспроизводимые дефекты и их регрессии, а не вывод по поиску слов `TODO`.
Тестовые FakeVenue/Socket/модель используются исключительно в тестах; рабочие
адаптеры не подменяют ответы биржи удачными фиктивными результатами.

Цена входа повторно проверяется по замороженным Fibonacci anchors после подтверждения:
контракт не разрешает погоню за ценой за пределами retracement 0.5–1.

## Проверка требований по пунктам

| Требование | Что реально выполняется | Существенная граница |
|---|---|---|
| AMD | Sweep → manipulation; дальнейшая направленная реакция → distribution; сжатие/объём относительно исторических медиан → accumulation | Может выдать unclassified. Это описание наблюдений, а не доказательство злого умысла |
| Карта ликвидности | Подтверждённые свинги, EQH/EQL, диапазоны, видимый стакан | Реальные чужие стоп-заявки публично не видны |
| Крупные игроки | Объём, крупнейший принт, флаг BT, OI, CVD, ликвидации и процентили | По агрегированному потоку нельзя установить владельца или его портфель |
| Вход после снятия ликвидности | Sweep локального диапазона + HTF POI + младший sweep/reclaim + новый контрольный блок | Строгий фильтр может отказаться от всех сделок; это не ошибка симулятора |
| HTF/LTF | 15m/1m, 1h/5m, 4h/15m; только закрытые бары и уже подтверждённые pivots | Нет полного контекста — вход запрещён |
| Быстрый старт | REST backfill 256 закрытых свечей каждого TF; лента поступает параллельно | Свечи не порождают фиктивные принты, L2 или обучающие метки; первой модели всё равно нужны наблюдения |
| Fibonacci/OTE | Направленные anchors; retracement 0.5–1; OTE 0.618–0.786 | OTE не объявлена статистически оптимальной |
| Сессии | Tokyo/London/New York, IANA DST; границы на графике | У криптофьючерсов нет единого официального закрытия торгового дня; это исследовательские сессии |
| Профиль прошлой сессии | Принты по реальным ценам, POC, смежная VA 70%, агрегированная гистограмма для графика | Первая наблюдавшаяся сессия может быть частичной и не используется как цель POC; старый полный профиль из одних OHLCV не выдумывается |
| Горизонтальные/вертикальные объёмы | Профиль и бары объёма, Delta/CVD, OI/ликвидации | Исторический REST объём не содержит buy/sell delta |
| FVG/имбаланс | Трёхсвечные разрывы, остаток незаполненного интервала | Разрыв не обязан заполняться |
| BAG | Строго определённый двухбарный gap вне предшествующего диапазона | В круглосуточном рынке может отсутствовать; отсутствие не заменяется «сильной свечой» |
| BOS/CHoCH/OB | Закрытые бары, подтверждённые свинги, смена направления пробоя, противоположная свеча | Операционные определения SMC, не универсальная истина |
| Теханализ | Трендовые линии, поддержки/сопротивления, флаг/треугольник как контекст | Не независимые статистические голоса за вход |
| RSI | Дивергенции на подтверждённых pivots | Не основной сигнал |
| Айсберги | Replenishment/absorption proxy по raw L2 и принтам | Нет order IDs и владельцев — доказанное обнаружение скрытого ордера не заявлено |
| Gamma Flow | Public option OI/Greeks/IV; gross exposure и изменения; IV/realized-vol risk scale ≤1 | Dealer sign неизвестен; это не signed GEX. У монет без опционов доступность явно false |
| Боковик | Нейтральная HTF-структура, граница/sweep, цель POC при достаточном RR либо противоположная граница | Сначала все общие фильтры и net RR; нет обещания торговать в каждом диапазоне |
| Новости | Bybit + RSS/Atom по активам, время публикации и первого получения, негативный словарный NLP, чёрные окна | Это подключённые источники, не «все новости мира»; лексикон не понимает весь контекст текста |
| Анлоки | Tokenomist v3; точные проверенные cliff events; линейный выпуск отдельно как supply context | Нужен ключ поставщика; AI/месячная точность не превращаются в минутное событие. Линейный выпуск не является дискретным blackout |
| Актуальность | Отдельные health/age по источникам, отсутствие покрытия блокирует вход | Макрокалендарь требует обновления. После исчерпания календаря система блокирует входы, а не обещает вечную актуальность |
| Обучение | Три условные ridge-модели; созревание меток, purged chronological fit/cal/test, периодическое переобучение | Не RL; rolling validation не равна навсегда независимому OOS |
| Контракт реакции | Единственный следующий checkpoint, flow/refill/retention, опровержение и deadline | Не выбирает удачный момент проверки задним числом |
| Стоп/трейл | За sweep и границей HTF POI; не меньше ATR/хвоста/спреда; биржевой stop; трейл только ужесточается | Slippage/gap/liquidation/network risk не исчезают |
| Риск | Сделка, день, портфель, маржа, участие в глубине, лот/шаг, net RR≥2 | Низкий риск не делает отрицательное ожидание положительным |
| Многопоточность | Market actors, raw socket/heartbeat, единственный account writer, trainer, news pool, history, options, archive, maintenance, HTTP | Python GIL и общая БД существуют; бесконечного масштабирования и формального отсутствия всех гонок не заявлено |
| Исполнение | Долговечная outbox, повторная авторизация, execId dedup, unknown-result reconciliation, реальные partial fills | Неизвестный результат не превращается в отказ и не повторяется вслепую |
| UI | Свечи/зоны/Volume/CVD/уровни/сессии, контракты и исполнения, stop/target, покрытие новостей, состояние/позиции/P&L/решения, Demo/Live/pause/flatten/ключи | Синтаксис, JS-ветви и SSE проверены; полноценная визуальная приёмка в Chromium здесь не выполнена |

## Данные новостей и конфигурация

`infra/fusion.news-sources.example.json` содержит два официальных источника.
Скопировать в `<userdir>/news_sources.json`; список перечитывается при запуске.
Для новой монеты нужны соответствующие symbol в config и источники, например:

```json
{"name":"arb-unlocks","kind":"unlocks","token_id":"arbitrum","assets":["ARBUSDT"]}
```

Это строка источника в списке, а не готовая полная конфигурация: отдельно нужен
RSS/Atom эмитента. Tokenomist-ключ вводится в консоли; хранение —
`<userdir>/secrets/tokenomist.json`, режим 0600. Он не выдаётся в status или backup.
Сторонний ключ не заменяется Bybit-ключом. Отсутствие ключа видно в health источника.

Исходный макрокалендарь: `infra/calendars/macro.csv` либо
`CAPITALIZATOR_MACRO_CSV`. Для каждого CPI/FOMC/NFP/PCE требуется известное заранее
будущее событие; при исчерпании покрытия входы блокируются. Обновление этого
календаря пока не автоматизировано. Даты событий не извлекаются угадыванием из заголовков.

`news_poll_s=60`, `context_poll_s=60` — бюджеты опроса внешних REST/RSS, не задержки
обработки котировок. `chart_refresh_s=0.2` ограничивает частоту передачи UI.
У брокера пробуждение по событию и максимум 100 мс ожидания обслуживания таймеров.
Пять секунд минимальной длительности торгового блока — горизонт определения
сигнала; их удаление изменило бы сам алгоритм и обучающие метки.

## Проверки и результаты

- Полный набор: **2241 passed, 2 skipped**; 86 тестов Fusion, включая 33 новых регрессии этого аудита.
- После уточнения пробуждения приватной очереди отдельно повторены все 86 тестов Fusion.
- Ruff: весь `src`, `tests`, benchmark. Mypy: исходная область и отдельно 24 модуля Fusion.
- JavaScript: синтаксис и исполнение ветвей на строгом DOM/canvas test double; это не браузерный скриншот.
- HTTP/SSE: реальные локальные запросы, новая свеча в потоке, разделение mode, штатная остановка до закрытия БД.
- Архив/backup: согласованный снимок SQLite и восстановление последовательности событий из его архивов.
- Raw WS: protocol fixtures, subscription rejection, сохранение delta, закрытие потоков. Авторизованных вызовов Bybit не было.
- Сборка wheel и включение HTML/новых модулей проверены; Docker в среде отсутствует.

Локальный синтетический прогон **10 000 book events**, два конкурирующих market
actor, SQLite WAL/FULL: **0.842 с, 11 874 событий/с**. BTC/ETH обработали по 5000;
p99 — **1.041 / 0.980 мс**. Это обработка небольших book frames без сети, модели и
биржевого matching. Результат не является SLA и не измеряет end-to-end latency.
Воспроизводимый инструмент: `tools/benchmark_fusion.py`. Значения меняются между машинами.

Полный двухлетний replay, доходность/Sharpe/PF/WinRate стратегии на реальном OOS,
сравнение с Buy & Hold/MA и доказательство преимущества **не получены**: нет
соответствующего массива L2 и подтверждённых счетовых исполнений. Имеющийся
A/B/C/D replay проверяет вклад компонентов и модель исполнения, не «все стратегии мира».
Требуются нетронутые интервалы, учёт издержек и отдельная проверка Demo, затем Live.

## TradingAgents и источники

[TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents)
рассмотрен как исследовательская архитектура аналитических ролей и противоположных
гипотез. Он не даёт свидетельства гарантированной прибыли или высокочастотной
надёжности. Синхронные LLM-вызовы в горячую ветку исполнения не добавлялись.
Текущий контракт уже хранит альтернативную гипотезу и будущий критерий опровержения.

Протокол и доступность полей проверялись по первичным источникам:

- [Bybit public orderbook](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook).
- [Bybit option tickers: gamma, OI, markIv](https://bybit-exchange.github.io/docs/v5/market/tickers).
- [Bybit Demo Trading](https://bybit-exchange.github.io/docs/v5/demo).
- [Tokenomist Unlock Events v3](https://docs.tokenomist.ai/api-documents/unlock-events/v3).
- [pybit WebSocket implementation](https://github.com/bybit-exchange/pybit/blob/master/pybit/_websocket_stream.py).

Прямую доступность внешних endpoint из среды исполнения подтвердить не удалось:
сетевой запуск проверки был остановлен до разрешения соединения. Это не результат
успешной интеграции и не доказательство недоступности endpoint на вашем VPS.
