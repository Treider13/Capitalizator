## Операционные изменения

- Постоянный отказ закрытия имеет состояние failed и код close_rejected в журнале команд. Новые входы по этому символу остаются заблокированы. После устранения причины повторное операторское «закрыть» возобновляет эту же команду. Подтверждённое отсутствие позиции и активных заявок завершает её без повторной отправки.
- При неизвестном результате создания reduce-only заявки пустой lookup по-прежнему недостаточен для повторной отправки — в том числе после перезапуска.
- Старые записи сохраняются; миграция не удаляет исполнения. Если старый Demo-журнал содержал другие категории, Live требует повторной квалификации по исправленному расчёту.
- Метка времени источника появляется в новых history-событиях. Старые журналы без неё читаются совместимо; отсутствующее историческое время нельзя восстановить задним числом.
- Модель данных по-прежнему использует один аккаунт на режим Demo/Live; этот набор исправлений не вводит миграцию журналов между разными аккаунтами.

## Проверки

Регрессии находятся в tests/fusion/test_confirmed_audit_fixes.py и tests/fusion/test_audit_fix_integration.py. Это тестовые имитации внешнего транспорта; рабочие REST/WS, БД, очереди и модель остаются настоящими.

На исходной версии: 37 падений и 9 успешных контролей. На исправленной: 46 успешных проверки. Полный набор: 2429 passed, 1 skipped (штатный тест необязательного внешнего инструмента). Ruff: src/tests без замечаний. Mypy: 29 модулей Fusion и 11 модулей стандартной конфигурации без ошибок. Проверка dashboard: 28 сценариев.

Проверки доказывают исправление указанных последовательностей событий. Реальные торговые операции и развёртывание на действующем счёте в этой проверке не выполняются.

## Повторная проверка исправлений

Два дополнительных теста выявили неполное покрытие F05 и F12 уже в первом наборе исправлений: при ошибке истории список отмен оставался пустым; после неверного кадра все четыре replay-варианта передавали разрешение входов на новостном событии. Исправления устраняют ранний выход перед отменами и учитывают остановку во всех ветках replay. Тесты сначала упали, затем прошли с теми же поведенческими требованиями.
