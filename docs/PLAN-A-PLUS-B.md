# План на утверждение: организм A + B

**Дата:** 2026-09-01  
**Статус:** ждёт утверждения. Код по этому файлу не писать, пока нет явного «утверждаю».  
**Канон:** `PRODUCT.md`, `IMPLEMENTATION.md` §4–6, `TEAM-DESK.md`, `INVENTION-JURY.md`, `INVENTION-FIRST-FACT.md`, `PHASES-ALL.md` §8а.

Замысел заказчика (обязателен, не иначе): во время сессии система **максимально собирает и взвешивает** новости (плановые и внезапные), причины, плюсы и минусы, объёмы, стены, крупных игроков, скринер, авторов. Контур **B** это видит и готовит тезис / вето / урезание / предложение. Контур **A** смотрит зону, книгу, свечу, BTC и **имеет последнее слово** на вход. Если тезис открытой сделки умер — выход. Если пошло — половина на +1R, остаток ведём стопом за структурой.

Это не четыре отдельных бота. Это один такт: **B собрал картину → A подтвердил или отказал → риск подписал → управление ведёт**.

---

## 0. Законы организма (не обсуждаются в реализации)

1. **A последнее слово на вход.** B не пишет ордер, не поднимает риск, не предлагает долить. Нет `average_in`.
2. **B имеет право убить и урезать** без согласия A: внезапный макро, несущий `REFUTED` / `UNVERIFIABLE`, окно CPI/FOMC, анлок, стена без ленты как запрет «держать декорацию».
3. **Нет зоны / нет ACCORD / нет первого факта (жест, n≥20) — входа нет.** Середина диапазона не торгуется.
4. Жюри не усредняет. Спорят книга и свеча — стоп. Это не «все факторы по чуть-чуть».
5. ИИ без ключей, без egress вместе с ключами, `trade_advice=false`. VERIFIED ставит верификатор / SQL / календарь, не модель.
6. Telegram / скрейп / типсы — запрет. Источники только allow-list.
7. Одна позиция. Стоп на бирже сразу. Механический БУ на +2% запрещён.
8. Вселенная входа: 24 линейных USDT-перпа Bybit. Чужой тикер B **анализирует и предлагает**, A **не шлёт** перп-ордер, пока тикера нет в `infra/universe.yaml`.
9. Скрытый лимит / айсберг не выдумываем. Видимые глубина, лента, доливки, стены — да.

## 1. Кто что видит (чтобы B не был «только заголовки»)

### Контур B — аналитик (всегда считает, ≥60 с на нарратив, секунды на календарь/объём-снимок)

B **обязан** иметь в карточке не только текст новости, а ту же рыночную картину, о которой был замысел:

| Слой | Что кладём в карточку как claims | Откуда |
|---|---|---|
| Новость плановая | CPI/FOMC/NFP/PCE, два часа, `size_rule` | `macro.csv` + живой официальный фид |
| Новость внезапная | `OTHER` / `FOMC` / `HACK` / `SEC` / `ETF` с `known_at=сейчас` | официальный RSS/JSON (Fed, BLS, биржа, наш allow-list) |
| Плюсы и минусы | 5–7 атомов, **хотя бы один минус**, негативный аналог обязателен | разбор + `reaction_prior` + наша память |
| Объёмы книги | `depth_near` до/после, imbalance top-5 | тот же L2, что A |
| Лента | `tape_eaten`, qty тейкеров за 8 с, сторона | тот же tape |
| Крупные лимиты / стены | wall appeared / pulled / eaten; четыре корзины ZLG | WallWatch + ZLG |
| Скринер | вселенная, спред vs ход, анлок сегодня/завтра, volume_ok | `Screener` + unlocks |
| Авторы | сырой пост → claims → hit/miss; вес не accept | RSS / reddit_json / свой TV |
| Киты | изменение когорты или честный «нет фида» | HL когда будет; до фида UNVERIFIABLE, не фейк-кошелёк |
| Листинг / новый токен | класс `LISTING`, потенциал, базовая ставка «заголовок часто минус» | официальный блог/RSS биржи |

Выход B на каждое событие и на каждое касание:

```
CardLive {
  card_id,
  thesis,
  pluses[], minuses[],          # человекочитаемый срез claims
  bearing_verdict,              # VERIFIED | REFUTED | UNVERIFIABLE | pending
  action: veto | cut_size | propose | hold,
  size_mult,                    # 1 | 0.5 | 0
  venue: perp | spot_proposal,  # spot только предложение, см. §5
  symbol,
  volume_snapshot { depth_near, eaten, walls, zlg_A_* },
  known_at
}
```

`propose` **не ордер**. Это тезис для A.

### Контур A — рука (последнее слово на вход)

На том же `touch_id` / той же карточке A считает: зона заранее, ZLG 8 с, CAV на закрытии, BTC, жюри Accord-or-Silence, риск, окно 16:30–19:30 МСК.

```
вход = B.action ∈ {propose, hold}
     ∧ B.bearing на несущих = VERIFIED (или B.action=veto уже убил)
     ∧ A.jury = ACCORD
     ∧ A.зона не mid
     ∧ символ в 24
     ∧ риск + сессия + макро.allow
     ∧ first_fact = жест с n≥20
```

Если B = `veto` — A не спорит, send нет, открытую позицию режет управление.  
Если B = `propose`, A = `SPLIT`/`SILENCE` — входа нет, в журнал пишем skip.  
Если A = `ACCORD`, B = `pending` — в полной системе send нет (дыра «A ждёт B» закрывается честно, не обходом).

### Управление (уже в каноне, дописать стык)

- +1R → −50%.
- Остаток: `trail_stop` за последним свингом/зоной, не вход+2%.
- Несущее `REFUTED` → `flatten` сразу.
- Внезапный макро / CPI-окно на открытой сделке → flatten или запрет новых; не «подождём».

## 2. Чего не хватает сейчас (перепроверка кода)

Скелет A живой. Атомы B лежат рядом. **Стыка нет.**

| Нужно по замыслу | Сейчас | Дыра |
|---|---|---|
| Календарь всегда в desk | `DeskLoop.calendar` часто `()` | плановый CPI не доходит до жюри |
| Внезапная ФРС | только заранее прошитый CSV | нет `known_at`-насоса |
| Карточка на касание | night `pending_card` с пустышками `pending-0` | нет плюсов/минусов, нет bind |
| `bearing_verdict` | поле есть, никто не пишет | `propose` в demo/live требует VERIFIED → send мёртв или обходится |
| Макро ×0.5 | `MacroRules` считает | qty не умножается |
| Стена без ленты | WallWatch есть | в цикле `wall_no_print=False` |
| Объёмы в B | A считает eaten/ZLG | в карточку не кладутся |
| Скринер «крупные игроки» | `Screener.ok` = спред/анлок/вселенная | не читает стены; стены надо дать B из WallWatch+ZLG |
| Авторы | `sources: []`, нет насоса | люди не читаются |
| Киты | `whale_accepts` всегда false | честный отказ; фида нет |
| Листинг → предложение | класс `LISTING` в схеме CSV | строк нет, спот-рельса нет |
| Flatten по новости | `on_refute` + desk `flatten` | некому поставить REFUTED с ленты |
| Следующая зона / трейл | `trail_stop` есть | `next_target` в snapshot не кладётся; трейл не вшит в живой manage-цикл |
| Экран фактов | консоль = статус/журнал | нет DOM касания (зона, глубина, стена, карточка, почему skip) |
| Живой send | signer-заглушка | отдельно от A+B; не блокирует стык тени |

`require_card=False` у desk при требовании VERIFIED в `propose` — противоречие. В полной сборке: desk **всегда** получает `CardLive`, голос карточки живой, send без несущих VERIFIED запрещён явно, не случайно.

## 3. Рабочие пакеты (порядок сборки)

Не «сначала энциклопедия». Сначала швы, без которых примеры 1–4 не живут.

### П0. Контракт касания A↔B

Один объект `TouchContext` на `touch_id`:

- поля A: зона, ZLG, A_*, eaten, CAV, BTC, jury;
- поля B: card_id, pluses/minuses, bearing, action, size_mult, volume_snapshot, news_class, known_at;
- управление: open | reduce | trail | flatten.

Тест: два прогона одной ленты → бит-в-бит тот же контекст. Без этого пакета остальные не начинать.

### П1. Живой календарь + внезапные события

- Desk **всегда** грузит `macro.csv` (уже есть ближайшие CPI/FOMC/NFP/PCE).
- Насос официальных фидов: Fed press, BLS, Bybit/Binance announcements RSS, allow-list из `sources.yaml`. Каждый кадр: `event_time`, `known_at=recv`, `class`, `assets`, `source`.
- Внезапная речь Пауэлла = новая строка `FOMC` или `OTHER` с `known_at=сейчас`. Lookahead невозможен.
- `MacroRules.size_mult` копировать в `Intent.qty`. Блекаут 14:00–15:00 ET — veto входов и flatten, если несущее было «спокойный макро».

Приёмка примера 1: фикстура «внезапный FOMC в окне стола» → новые входы `sent=false`, причина `macro_veto` / `bearing REFUTED`; открытый лонг → `flatten`.

### П2. Карточка плюсов и минусов на касание и на открытую позицию

- Сборщик (схема, не свободный чат): новость + volume_snapshot + зона + BTC → 5–7 claims, минимум один `load_bearing`, минимум один минус.
- Верификатор: числа из PIT/журнала/календаря. Нет файла-доказательства → `UNVERIFIABLE` → нет входа, не выдумка.
- ИИ (карантин): может набросать формулировки. Не ставит VERIFIED. Не пишет «купи».
- Открытая позиция: тот же цикл раз в N секунд. Несущее умерло → `on_refute` → flatten.

Приёмка примера 3: фикстура «ETHUSDT в лонге + HACK/OTHER known_at сейчас, несущий лонг REFUTED» → flatten в том же такте, не «выход в безубыток на глаз».

### П3. Объёмы и крупные лимиты в B (то, чего в B сейчас нет)

B на каждом касании и на каждом `propose` **обязан** заполнить `volume_snapshot`:

1. `depth_near` стороны зоны до удара;
2. тейкеры за 8 с и `tape_eaten`;
3. события стен: appeared / pulled / eaten;
4. ZLG `A_same, A_back, A_in, A_opp` + жест;
5. imbalance(5);
6. флаг скринера: символ свой, анлок, спред vs ход, volume_ok.

Правила (B пишет в карточку, A голосует лентой как раньше):

- стена `pulled` без печати → B не зовёт «держать», A ставит `wall_no_print` (снять хардкод `False`);
- крупные add на стороне зоны (`DEFEND`/`IMPROVE`) + новость+ → B может `propose`;
- крупные add без зоны / mid → B не предлагает, A не торгует середину;
- «скрытый лимит» в карточке запрещён.

Скринер остаётся фильтром вселенной. «Крупные игроки ставят лимиты» — это WallWatch+ZLG **внутри B**, не новый DOM-сканер 200 монет.

### П4. Склейка в desk (A читает B)

В `_eval_cav_and_jury` и `propose`:

1. подставить календарь;
2. посчитать volume_snapshot (П3);
3. взять/собрать `CardLive`, записать `bearing_verdict`;
4. `wall_no_print` из стен;
5. `size_mult` из макро и B.cut_size;
6. `next_target` = ближайшая зона против хода, иначе 2R;
7. `require_card` согласовать с законом: нет карточки → нет send в demo/live; тень пишет «вошёл бы, B молчит».

Жюри: пять голосов как сейчас. Голос card больше не `None→0` по забывчивости, а явный pending/VERIFIED/VETO.

### П5. Листинг и «предложить спот» (пример 2, без смены позвоночника втихую)

Два выхода, оба обязательны, чтобы замысел не потерялся:

**A. Тикер уже в 24 перпах.**  
B: карточка LISTING/новость, плюсы/минусы, объёмы.  
A: если ACCORD — вход перпом по правилам стола. Не «купил заголовок».

**B. Новый токен / спот, которого нет во вселенной.**  
B пишет `venue=spot_proposal` в очередь предложений (консоль + knowledge).  
Текст: потенциал, минусы, базовая ставка листингов (часто день 1 слабый, дальше минус).  
**Ордера нет.** Человек видит предложение. Чтобы система сама купила спот — отдельное утверждение: спот-адаптер Bybit + ручной ack на новый символ + лимит риска. Без этого ack пример 2 = «система знает и предлагает», не «сама купила BNB-новый».

Это не отказ от замысла. Это единственный способ, при котором «предлагает на спот» работает в день утверждения плана, а не ломает закон 24 перпов молча.

### П6. Позитив + A подтвердил + трейл (пример 4)

Цепочка в одном тесте:

1. Позитивная новость по символу из 24, `known_at` честный.
2. B: плюсы и минусы, volume_snapshot (глубина не съедена, стена не pulled, ZLG DEFEND/IMPROVE), скринер ok → `propose`.
3. A: зона, CAV REJECT, жури ACCORD, BTC не против → intent.
4. Fill → +1R reduce 50%.
5. Цена растёт, `trail_stop(last_swing)` ползёт. Выбило по структуре — плюс на остатке.
6. Контроль: та же новость без зоны / mid / SPLIT → send нет.

### П7. Экран фактов касания

Консоль (127.0.0.1): по последнему touch — зона, глубина, eaten, четыре A_*, стены, CAV, BTC, pluses/minuses, bearing, jury, skip_reason, B.action. Ордеров отсюда по-прежнему нет. Это чтобы «видеть стакан» = видеть то, что считает организм, не второй CScalp.

### П8. Авторы и киты (после П0–П6)

- Заполнить `sources.yaml` живыми https RSS/reddit_json/свой TV (сейчас `sources: []`).
- Насос → `author_call` с `known_at`. Вес с n≥5. `author_accepts` остаётся false: автор не открывает.
- Киты: HL-когорта когда фид будет; до фида карточка честно `UNVERIFIABLE` на claim «кит», вход от этого не открывается.

## 4. Приёмка четырёх картинок замысла

| # | Сценарий | Обязательный исход |
|---|---|---|
| 1 | Внезапная ФРС в сессии | B узнаёт (`known_at`), пишет причины за/против, **не входит**; если были — **flatten**. Не ловит первый тик. |
| 2 | Анонс токена / листинг | B анализирует потенциал и минусы. В 24 → может `propose` для A. Не в 24 → `spot_proposal` на экран, ордера нет без отдельного ack. |
| 3 | Резкий негатив ETH, мы в лонге | Несущий REFUTED → flatten в том же такте. Не механический БУ. |
| 4 | Позитив по монете из 24 + объёмы/лимиты + A да | B propose с volume_snapshot; A ACCORD; 50% на 1R; трейл за структурой до выбивания. |

Общий негативный тест: красивая новость + B propose + A SPLIT → **нет входа**. Последнее слово A.

## 5. Что не входит в этот план (чтобы не разъехаться)

- Скрейп Telegram/Discord, покупка типсов, 2-секундный градиент групп.
- Мультибиржевой стакан как вход (Binance L2 не открывает Bybit).
- Fib/RSI/FVG/GEX как голос жюри.
- Выдуманные айсберги.
- ИИ жмёт кнопку.
- Слот «спот сам купил новый тикер» без отдельного утверждения П5-B.
- Ломать окно 16:30–19:30 МСК «потому что новость ночью» — новость ночью пишет карточку и flatten, **новый** вход всё равно только в окне (кроме flatten/защиты, которые всегда можно).

Flatten и veto защиты — 24/7. Новые входы — окно стола.

## 6. Критерий «полноценно», не обрубок

Организм собран, когда на одной фикстуре ленты + новости:

1. B заполнил карточку (плюсы, минусы, объёмы, стены, скринер).
2. A вынес jury.
3. В журнал нет пустого `bearing_verdict` при ненулевом касании.
4. Макро ×0.5 видно в qty.
5. `wall_no_print` может стать true.
6. Примеры 1, 3, 4 зелёные автотестами.
7. Пример 2 зелёный как propose + spot_proposal (ордер спота — только если утвердят П5-B отдельно).
8. Консоль показывает тот же touch, что тест.

Пока пункты 1–6 не зелёные — это ещё заготовка B и дырявый A, даже если модули лежат в `src/`.
