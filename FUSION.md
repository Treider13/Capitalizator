# Эксплуатация Fusion

## Установка и запуск

Поддерживаемая среда эксплуатации — Linux, Python 3.12. `fcntl` обеспечивает
одного владельца каталога счёта. Основной установочный набор — `.[live]`;
`.[dev,live]` дополнительно ставит средства статической проверки и тестирования.
`tzdata` обеспечивает IANA-зоны для Tokyo, London и New York, включая DST,
когда системная база часовых поясов отсутствует.

```bash
python -m pip install -c requirements.lock -e ".[dev,live]"
python -m pip check
python -m capitalizator.fusion --userdir /absolute/path/to/fusion-data
```

Если передан `--config`, читается именно этот файл; отсутствующий файл,
каталог вместо файла или ошибка чтения останавливают запуск. Defaults при
ошибке явно выбранного файла не используются. Иначе читается `config.json`
в userdir, а при его отсутствии используются значения `Config`.
Существующий `config.json` сохраняет свой список пар: для перехода со старых
BTC/ETH на шесть выбранных инструментов перенесите `symbols` из `infra/fusion.default.json`,
сохранив свои остальные лимиты, и перезапустите сервис с закрытым счётом.
Новая версия конфигурации инвалидирует прежнюю модель/Live-квалификацию.

Контур spot+linear включён для всех config.symbols, кроме XAUUSDT. Для золота
проверяется только фьючерсный стакан; spot отмечен `not_required`. Для остальных
пар отсутствующий, невалидный, устаревший или встречный по давлению стакан
любого из двух рынков запрещает новый вход. Подмены XAU на PAXG/XAUT нет.
Политика `fusion-11-xau-linear-model-gates` инвалидирует старые модели и
Live-квалификацию; требуется новая проверка и Demo-история. Сохранённая пауза
не снимается обновлением. `passed=false` блокирует Live, но само по себе не
запрещает Demo: там остаются проверки сигнала, контракта, данных и риска.

## Диагностика перезапусков и модели

`/api/health` возвращает 503 при ошибке, остановке или просроченном heartbeat
worker, включая trainer/maintenance. Heartbeat учитывается с начала потока.
Неожиданный return worker считается аварией. Пауза входов и отклонённая модель
сами по себе не являются аварией.
Compose использует этот endpoint; Docker healthcheck только отмечает состояние,
а не перезапускает контейнер. Ошибка worker теперь завершает CLI с кодом 1.

В `userdir/logs/runtime.jsonl` пишутся startup, изменения паузы, ошибки с полным
traceback и shutdown. Каждые 60 s записываются очереди и возраст heartbeat.
Отдельный watchdog сохраняет Python-стеки при переходе в stale и сообщает
восстановление. После нового heartbeat он снимает только свой worker_stale,
сохраняя паузу и другие причины запрета. Журнал ротируется: текущий файл плюс
три по примерно 5 MB.
`last_failure.json` атомарно сохраняет первую ошибку аварийного запуска; ошибки
очистки не затирают её. Она видна после нового запуска через `/api/status`.
Диагностика также пишется в stderr. Известные форматы ключей маскируются;
locals и полная конфигурация не записываются. В Compose включён Python
faulthandler для диагностируемых нативных сбоев в stderr. SIGKILL, OOM и падение хоста
требуют дополнительно Docker/journald: Python не может записать их после смерти.

Короткая сводка с телефона (только чтение):

```bash
docker exec capitalizator-fusion-1 python -m capitalizator.fusion.diagnose --userdir /data/fusion
```

`--pair SOLUSDT` сокращает вывод до одной пары; `--json` даёт подробный JSON.
Сводка читает до 20 000 последних записей decisions в SQLite read-only с лимитом
времени запроса. Это частоты записанных причин разных этапов, не вероятности
входа и не вся история. Новые entry_not_authorized дополнены `blockers`:
paused, broker_not_ready, news_coverage_unavailable и другими причинами.
Готовность книг в сводке не разрешает сделку и не отменяет остальные фильтры.

Последнее необработанное исключение:

```bash
docker exec capitalizator-fusion-1 cat /data/fusion/logs/last_failure.json
```

Для независимой хронологической проверки записанных samples (чтение SQLite,
без отправки заявок) доступен `python -m capitalizator.fusion.model_audit --userdir
/data/fusion`. В shell пишите команду одной строкой. Он использует политику,
записанную в БД, и текущий алгоритм оценки. Возвращаемые результаты — proxy по
меткам, не доходность счёта: сделки, SMC, новости и риск проверяются отдельно.
Новые отчёты модели показывают число сигналов, издержки, силу предсказания,
горизонт/длину истории и причины отказа. `training_timeout_s` ограничивает
всю передачу задания/ожидание результата дочернего обучения (default 120 s),
плюс ограниченное время завершения зависшего процесса. Если канал был прерван,
он не используется повторно. Закрытие не отправляет данные в заполненный pipe.

## Счёт и управление

Ключи хранятся в `secrets/demo.json` и `secrets/live.json` с правами 0600.
Альтернатива — переменные `CAP_DEMO_KEY`, `CAP_DEMO_SECRET`,
`CAP_LIVE_KEY`, `CAP_LIVE_SECRET`. Значения не печатаются и не сохраняются в Git.

«Пауза входов» прекращает допуск новых входов и инициирует отмену оставшихся
входных заявок; защитный брокер продолжает работать. «Закрыть позиции» создаёт
долговечные команды закрытия по настроенным символам. Фактическое закрытие
подтверждается состоянием Bybit, а не нажатием кнопки или ответом REST.
Исполнение команды закрытия также отзывает связанные торговые контракты:
поздно появившаяся позиция после terminal cancel требует защитного выхода.

Изменение торговых лимитов требует паузы и отсутствия позиций и неразрешённых
заявок. При подключённом счёте требуется свежая сверка REST. Настройки
сохраняются атомарно; приложение завершает старые workers, перезапускает
контуры с новым неизменяемым Config и остаётся на паузе. SSE переподключается.
При запуске не через штатный CLI вызывающая программа должна обработать
`runtime.restart_requested` и создать новый Runtime после закрытия старого.

Live требует прошедшей хронологическую проверку модели и не менее 32 закрытых
Demo-эпизодов текущей политики, полной реконструкции инвентаря и положительной
нижней bootstrap-оценки net результата. Эти программные условия не доказывают
достаточность истории для реального риска и не заменяют длительный forward run.

## Новости

В консоли можно добавить/удалить RSS/Atom и источники Tokenomist, указав пары.
Сохранение требует паузы. Старые результаты не подтверждают новую редакцию
источников: покрытие отзывается до новой загрузки. Настройки сохраняются в
`news_sources.json`. Ключ Tokenomist хранится отдельно в `secrets/tokenomist.json`.
Если файл источников уже существует, он сохраняет приоритет над defaults.
Обновите его через редактор для новых пар. Флажок «Только упомянутые активы»
фильтрует общую ленту по явным названиям/тикерам; с ним `ALL` недопустим.
Глобальный `ALL` означает заявленную оператором область источника; он не
является доказательством исчерпывающего покрытия всех новостей всех монет.

## Развёртывание

```bash
docker compose -f infra/deploy/compose.yml up -d --build fusion
```

Compose запускает один сервис Fusion. Консоль слушает loopback; для удалённого
доступа используйте SSH tunnel `ssh -L 8082:127.0.0.1:8082 trader@server`.
Прежние Compose/Dockerfile с суффиксом `.legacy` относятся к историческому
контуру; не запускайте их одновременно на одном счёте с Fusion.

## Данные и восстановление

`fusion.sqlite3` содержит события, решения, модели, контракты, outbox и уникальные
исполнения. Старые события архивируются в `archive/*.parquet`: fsync/rename
предшествует удалению диапазона из SQLite. Не удаляйте неопределённые заявки:
пустой REST lookup после timeout не доказывает, что отправка не состоялась.

```bash
python -m capitalizator.fusion.backup --userdir /absolute/path/to/fusion-data --dest /absolute/path/to/new-backup
```

Резервная копия содержит SQLite и архивы из его manifest, конфигурацию и источники;
ключи в неё не входят. Пользовательский `--config` вне userdir копируйте отдельно.
Восстановление: остановить сервис, восстановить каталог, вернуть ключи отдельно,
начать со сверки счёта. Нельзя одновременно запускать оригинал и восстановленную
копию на одном Bybit-счёте: локальный lock защищает каталог, а не удалённый счёт.

## Проверки

```bash
ruff check src tests
mypy src/capitalizator/fusion --follow-imports=silent
git diff --check
python -m pip install -c requirements.lock -e ".[dev,live,hyexec,talib]"
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -m pytest -q -rs
```

Тесты включают синтетическую биржу, replay-сценарии, конкурентные очереди и
локальный HTTP/SSE. Это не результат торговой стратегии на рыночной истории.
Отдельный offline replay доступен через
`python -m capitalizator.fusion.replay --userdir ... --config ... --output ...`;
нужны реальные записанные события и спецификации инструментов.
